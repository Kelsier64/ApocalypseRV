# Player v021 locomotion

Seventeen authored in-place clips: looping `idle`, `jog_forward/back/left/right`, `run_forward/back/left/right`, plus non-looping `jump_rise`, `jump_fall`, and `jump_land`; looping `climb_hold`, `climb_up`, `climb_left`, `climb_right`, plus non-looping `climb_exit`. The user selected 5 m/s jogging and 8 m/s sprinting instead of changing gameplay speeds to match a walking gait. Physics remains 60 Hz.

The hand pose keeps wrist-only roll and relaxed fingers curving toward the palm, with progressively more curl from index to little finger and a gentle thumb bend. The wrist narrowing below the cuff remains as previously shown. Every key value in all twelve previous ground/jump clips is unchanged by the climb addition. [Jump checks and screenshots](../../../docs/validation/player-animations-v021/jump/verification.json) are separate from the [earlier finger revision](../../../docs/validation/player-animations-v021/relaxed-fingers/verification.json).

[Build script](../../../scripts/build_player_animations.py) reads the accepted external `player_godot_export_v020.blend` and writes [the editable copy](../../../art_source/player_animations_v021/player_animations_v021.blend) and this GLB. Bake rate is 60 animation samples per second, unrelated to the physics setting. Godot imports at 60 fps with animation optimization/compression disabled; default curve reduction caused boot penetration and must remain off. All 41 deform bones retain their rest transforms; ten controls remain in Blender and are excluded from export. The saved copy contains baked Actions with constraints disabled; the original v020 retains its live control setup.

The GLB contains the complete 11-mesh character for offline preview. Runtime only copies its animation resources into the original v020 model's AnimationPlayer; no new mesh, Skin, material, texture or rest pose replaces the accepted model. TEST/validation Actions are excluded. Each actor has an independent playback state and shares immutable clip resources.

Forward/back stance travel is authored for the existing speeds. Side variants use a narrower stride; diagonal selection uses the dominant direction, rather than a 2D blend or foot-placement IK. Ground transitions use 0.16-second blending. Jump pose changes read actual vertical velocity and floor contact: rise/fall clips reach a held pose in 0.2 seconds, then a 0.2-second landing compression returns to ground motion. New jumps interrupt landing immediately. UI freezes airborne playback alongside the existing controller pause; grab suspends animation and seats retain the existing hide/show behavior. No attack, crouch or seat animation is delivered in this batch.

Climbing reads actual carrier-relative displacement because controller velocity is zero in that mode. Hold/up/left/right clips blend in 0.08 seconds. A bounded pose-space root translation brings the authored palms toward the sampled wall plane without moving the player collider. The first-person eye shares that world-space offset, with free-look rotation unchanged; recovery unwinds both together. Ragdoll starts from the current eye and restores the neutral standing eye on respawn. Remove the previous offset before each animation blend to prevent accumulation. The existing instantaneous inward roof transfer triggers 0.3 seconds of arm recovery, including when floor contact appears one frame later. This is not a root-driven mantle or per-hand/per-foot contact IK; exact gripping on oblique walls and corners is not validated. See [climb acceptance](../../../docs/validation/player-animations-v021/climb/verification.json) and [close-up playground](../../../tests/player_climb_animation_playground.tscn).

Actual input-driven jumps and death handoffs pass. Three synthetic high-drop handoffs (root height 1.8 m with vertical velocity +4/-4 m/s) exceeded the existing 25 mm joint-gap limit, peaking at 29.12 mm. This remains a recorded ragdoll limitation; tick, solver settings, masses and joints were not retuned for these clips.
