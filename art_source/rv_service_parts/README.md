# RV battery bay, battery and fuel inlet

- Directly modeled native geometry: chamfered housings, enclosed turned fittings, visible handle/compartment openings, retaining clamps and contained leads. ComfyUI is not needed for these small, precisely fitted interfaces.
- Rebuild from repository root: `python art_source/rv_service_parts/build_models.py` (numpy required). Editable `.gltf` / `.bin` pairs are beside this file; `model_parameters.json` records counts, bounds and hashes.
- Runtime: `assets/models/rv_battery_bay/`, `assets/models/rv_service_battery/`, `assets/models/rv_fuel_inlet/`. Each asset is one mesh with material surfaces; no collision or gameplay script is baked into the GLB.
- Existing original wear texture is referenced externally, unchanged: `assets/materials/industrial/worn_paint.png`. Material colors are glTF linear values; plastic, rubber, contact metal and paint remain separate.
- Battery: 1,598 triangles, 0.45 × 0.30 × 0.30 m, original centered origin. Terminals and folded handle are included inside the envelope. `props/battery_large.tscn` still inherits the common battery and retains capacity/weight.
- Bay: 1,586 triangles, X [-0.16, 0.161], Y [-0.28, 0.28], Z [-0.475, 0.475] m; front +X. The additional 1 mm is the surface warning mark. Empty/full appearance still follows the direct-root `Cell:MeshInstance3D`, now containing the shared battery visual rotated +90° Y, scaled (1.3, 0.94, 0.75), at the existing Cell position (0.04, 0, 0). Fixed leads remain visible when empty.
- Fuel inlet: 1,750 triangles, X [-0.30, 0.30], Y [-0.15, 0.2355], Z [-0.20, 0.20] m; cap faces +Y. Existing -90° Z mounting in starter/new RV turns it outward +X. Cap height stays within the previous grip envelope; no opening animation added.
- Original wrapper roots, collision shapes, scene paths, interaction labels, item metadata, mounting faces and save behavior remain. Previous static graybox meshes remain hidden; the Cell's old cube mesh is replaced by its visual child. Dynamic charge text is moved onto the bay's lower faceplate.
- Validation 2026-10-11: Forward+ individual/front/back/underside and installed RV previews; native assertions for dimensions, installed-cell fit, empty/full visibility, unchanged collision/poses and outward cap direction. `test_rv_interactions`, `test_rv_systems`, `test_item_player`, `test_item_persistence` passed. No manual player walkthrough or FPS benchmark.
- Rebuild checks require finite geometry/unit normals, nonzero-area triangles and outward winding. Closed components intentionally overlap at fasteners/joins; these are static render meshes using the existing independent gameplay collision.
