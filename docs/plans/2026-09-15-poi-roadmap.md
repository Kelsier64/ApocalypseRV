## 1. 目前基礎與保留原則

以下基礎已依現行文件與程式更新；尚未驗收的擴充項目保留未勾選：

- 主世界提供四款室外外觀與入口，共用既有室內內容，短按 E 進入獨立 World3D 副本；回 R001 出口返回。
- 每個副本生成 50–100 間單層房間，有分岔、死路、環路與連通性保證。
- 目前只有 9×9 m 小房和 18×18 m 大廳兩種四門模板，固定 10 欄、27 m 中心間距。
- 家具與物資點預先配置；首次進入隨機抽取，每房最多 4 件。背包目前 6 格。
- 殭屍按房間編號間隔配置，尚無完整區域難度與探索節奏。
- 外部世界持續模擬，RV 油電與外部威脅繼續運作；串流錨點留在入口處。
- 離開後卸載副本模型，保留同局物品與存活敵人狀態；重返不重抽物資、不復活已死敵人。
- 目前每次進入都重建所有房間並烘焙導航，室外檢查點已保存已訪副本；任意已回收室外區塊的完整回訪仍未提供。
- 舊 POI 場景與生成器已刪除；後續內容沿用新資產與副本系統。

維持「預製房間隨機連接、房間有不同尺寸、物資點可設計、主世界持續運作」的方向。房間生成數量與獨特房型數量分開計算，不把 100 間生成房宣稱為 100 套內容。

新增確定方向：**副本由二維單層布局升級為三維多樓層布局**，包含可實際走上、走下的樓梯房與跨樓層房間。上面的單層描述是目前程式現況，不再是後續生成器的限制；本次只更新計畫，尚未實作。50–100 房仍指整個副本的總房數，不按每層倍增。

房間複雜度方向：保留多門連接與可繞回的路線，避免所有房間都只有單一出口；後續房型擴充須延續此要求。

### POI-01：深入探索的理由

現況：主要活動是沿途撿物，尚無深處目標，也沒有依實際探索路程安排的獎勵節奏。

待做：

- [ ] 為維修站安排至少一個深處目標，例如零件庫、供電控制室或特殊設備；實作時選定具體內容。
- [ ] 按入口的實際連通路程安排入口區、過渡區與深處區，不使用房間編號代替距離。
- [ ] 探索深度納入上下樓的實際路徑成本；樓層高低不直接等於難度或獎勵等級。
- [ ] 設計「現在撤退」與「繼續深入」的取捨，讓可見線索提示更深處的收益和危險。
- [ ] 保存目標完成與相關互動狀態，離開重返不重置。

驗收：從入口到目標可達；不同 seed 都能形成可理解的探索流程；一般搜刮與完成深處目標有可辨識的收益差異。

### POI-02：房型與布局變化

現況：兩種方形房在固定格網上反覆出現，總房數增加不等於內容多樣化。

待做：

- [ ] 第一輪擴充到 8–12 種可辨識房型，候選包含長房、L 型房、交叉廳、儲藏間與不同尺寸的大廳。
- [ ] 房型預算納入 POI-10 的樓梯房、跨層挑高房與樓上平台；跨層房算一個房間實例，但占用完整三維空間。
- [ ] 為房型製作不同家具配置，保持門口與主要通路淨空。
- [ ] 擴充占地、門位置、旋轉與連接規則，逐步支援不等寬、不等長與不同門數的房型。
- [ ] 控制房型權重、相鄰重複與特殊房數量；保留 50–100 房總量及全部房間連通。
- [ ] 改善固定 27 m 間距造成的走廊長度與規整感，避免新增房型後重疊或留下無法穿越的接口。

驗收：新房型有獨特用途或動線；混合尺寸與旋轉生成時不重疊、不封死必要通路；物理行走和導航皆能通過連接處。

### POI-03：迷路與返程體驗

現況：主要依房號辨認位置，必須找回 R001。

待做：

- [ ] 劃分至少三個可辨識區域，以色帶、用途、照明或地標提供方位線索。
- [ ] 加入玩家標記或探索紀錄；具體形式可選已探索地圖、路徑記錄或場景標記，不預先揭露整座迷宮。
- [ ] 顯示目前樓層、樓梯上下方向及已探索的跨層連接；探索記錄支援分層檢視，避免不同高度的房間混在同一平面。
- [ ] 設計從深處開通的返程捷徑，讓探索成果能縮短搬運與撤退路程。
- [ ] 保存已探索資訊和捷徑開啟狀態，避免重返後消失。

驗收：玩家能藉環境線索識別區域；找到目標後有更有效率的返回方式；導航輔助不直接消除未知區域的迷宮感。

### POI-04：物資與搬運平衡

現況：每房最多 4 件與 6 格背包尚未形成完整平衡，可能過早裝滿並反覆搬運。

待做：

- [ ] 設定副本總物資預算、區域物資類別與價值分布，避免單純按房數堆量。
- [ ] 依探索深度、房間用途與風險調整獎勵，保留靠近入口的基本補給。
- [ ] 評估推車或暫存點的必要性；先測量現有搬運成本，再決定採用方案。
- [ ] 結合返程捷徑，避免大型物品只能反覆走相同長路。
- [ ] 驗證搬運大型物品上下樓的通行空間；若採推車，需先決定其樓梯限制與替代搬運路線。
- [ ] 驗證物資供給能支援搜刮、回收、製作汽油及再次出發的循環。

驗收：完整遊玩一趟後記錄搜刮時間、滿包時機、搬運次數與實際收益；深入的收益應能支持其額外風險與時間成本。拾取、搬運、暫存及重返不得複製物品。

### POI-05：敵人配置與室內應對

現況：按房間編號固定間隔放殭屍，未反映路程、區域用途或目標價值。

待做：

- [ ] 改成依入口距離、區域危險度與房間用途配置敵人，保留入口緩衝。
- [ ] 規劃巡邏、固定守備與群體出現的配置規則，避免單純平均撒怪。
- [ ] 提供室內躲避、引誘或關門等應對方式；具體機制在實作時選定，不預設必須加入武器。
- [ ] 驗證窄門、家具、轉角與多隻敵人的實際追擊與脫離行為。
- [ ] 驗證敵人能沿樓梯跨層追擊和撤離；同 X/Z、不同樓層的玩家不得被隔著樓板攻擊或誤認為可直走抵達。
- [ ] 保留敵人不跨入口的隔離規則，並維持同局死亡狀態。

驗收：危險分布與環境線索相符；玩家有可操作的應對或撤退路徑；敵人不穿牆、不跨世界攻擊，群體不長期卡死必要通道。

### POI-06：入口與地形整合

現況（2026-09-15 更新）：地形已改為世界座標網格與共用整地查詢，完成路旁停車區、展寬支道、入口平台及三種小型搜刮停靠點。後續已增加四款外觀，但仍共用相同室內內容。[地形驗收紀錄](../validation/2026-09-15-highway.md)。

待做：

- [x] 建立公路、停車區、支道、入口平台之間的安置規則。
- [x] 限制坡度、落差與道路距離，檢查 RV 停靠空間、步行動線與返回落點。
- [x] 增加四款入口外觀，見 [室外驗收](../validation/2026-09-16-outdoor-horror.md)。
- [ ] 由 POI 類型選擇不同房間、物資與敵人配置。
- [x] 與地形重寫整合，讓既有入口模板落在整平平台並朝向公路；新模板仍須驗證各自占用範圍。

驗收：多組世界 seed 的入口可從公路抵達；RV 有合理停靠空間；玩家進出後不被地形、建築或停放車輛困住。

### POI-07：效能與異常復原

現況：每次進入都重建所有房間並烘焙導航；轉場失敗／逾時／取消復原已有 [R05 修正與測試](../report/ApocalypseRV_Fixes_2026-09-18.md)，大型副本長時間效能與下列完整情境仍需驗收。

- [ ] 先量測 50／75／100 房的首次載入、重返時間、幀率、記憶體及敵人處理成本，再設定效能目標。
- [ ] 納入不同樓層數、挑高跨層房與多層可見區域；遠處休眠與分區載入需考慮垂直距離及跨層追擊。
- [ ] 依量測結果評估布局／導航快取、遠處敵人休眠與分區載入；避免未量測就全面改架構。
- [x] 轉場失敗、逾時、取消與死亡時清理暫建世界並恢復控制，見 R05。
- [ ] 完善可量化載入進度，依 50／75／100 房量測驗收。
- [ ] 測試快速重複互動、轉場時死亡、返回位置被占用等邊界情境。
- [ ] 驗證多次進出不同 POI 後記憶體不持續無界成長，沒有殘留物理物件或子視窗資源。

驗收：記錄量測設備、引擎版本與效能數據；故障時不得永久停在 busy 或 UI 鎖定狀態；最佳化後保持同局保存、世界隔離和導航行為。

### POI-08：存檔與長期回訪

現況：F6 室外檢查點已保存已訪副本的 seed／物品／存活敵人，F9 可跨執行還原。尚未實作探索紀錄、目標、捷徑、多樓層資料及任意已回收室外區塊回訪。見 [保存修正](../report/ApocalypseRV_Fixes_2026-09-18.md)。

- [ ] 定義穩定的世界、入口、副本與互動物件 ID，及存檔版本與升級策略。
- [x] 透過室外檢查點保存既有布局 seed、物品與敵人狀態。
- [ ] 擴充探索紀錄、目標、門與捷徑狀態。
- [ ] 保存生成器版本、房間穩定 ID、三維 transform、跨層連接及必要的樓層識別；不可只用平面座標辨識房間或物品。
- [ ] 設計外部區塊重建及入口還原方式，使重新生成的入口仍能找到原副本。
- [ ] 處理讀取失敗、缺少資源及不相容版本，避免悄悄重置已搜刮內容。

驗收：離開遊戲後重開仍還原相同副本；外部區塊卸載與重建不產生新的副本身分；已拿物品與死亡敵人不重生。

### POI-09：房型資源表與製作工具

現況：入口、房間與家具可以編輯，但新增房型仍需修改程式中的模板選擇。

- [ ] 建立可在 Godot 編輯器配置的 POI／房型資源表，包含場景、尺寸、門接口、權重、區域、家具與物資配置。
- [ ] 配合 POI-10 加入三維占用範圍、跨層高度、各入口的完整 transform 與通行方式；樓梯上下端可有不同 Y 值，不能再假設所有門都在同一高度。
- [ ] 讓生成器讀取資源表，降低新增房型時修改生成程式的需要。
- [ ] 提供指定 seed 的一鍵預覽、重新生成、單房檢查及布局總覽。
- [ ] 預覽支援切換樓層、剖面或隱藏上層幾何，讓樓梯、樓板與跨層碰撞可直接檢查。
- [ ] 加入尺寸、接口、通道淨空、重複 ID、缺少資源與標記位置的驗證回饋。
- [ ] 保持模型外觀、碰撞、門接口與物資點分層，方便正式模型逐步替換灰盒。

驗收：能透過新增資源與場景加入一種房型；不相容內容在製作階段即可定位；預覽與正式遊戲對相同 seed 使用相同生成規則。

### POI-10：三維布局與上下樓房間

需求：從目前 X/Z 平面上的房間連接，升級為 X/Y/Z 空間中的多樓層迷宮。玩家在同一副本內實際走樓梯上下移動，不以逐層傳送取代樓梯通行。

待做：

- [ ] 將布局資料、占用檢查與連通圖改為支援三維座標及帶高度的連接；上下樓屬於同一張探索拓樸，不是彼此無關的平面迷宮。
- [ ] 定義樓層標高、樓板厚度、淨高與垂直模組規格，區分房間淨高和樓層間距；先以可配置的 2–3 層驗證，實際上限依內容與效能決定。
- [ ] 製作樓梯房，包含低處入口、階梯、轉折平台與高處出口；也能從高處往低處通行。優先完成一般步行樓梯，梯子、電梯保留為後續擴充，不恢復已刪除的舊電梯生成器。
- [ ] 製作跨層挑高房、樓上平台或帶內部樓梯的雙層房，讓上下樓可發生在同一房間內；上下接口不必位於相同 X/Z。
- [ ] 為房間定義完整三維占用體積或占用格集合，包含樓板、樓梯、平台和必要淨空；挑高空間不可被另一層房間填入。
- [ ] 依門接口的完整 transform 接合房間與垂直連接模組，檢查高度、朝向、開口尺寸、樓梯終點與頭頂淨空；不能只把既有房間任意抬高。
- [ ] 生成時安排必要的跨層連接，檢查所有可探索房間都能從主入口抵達並沿合法路線返回；支援由不同樓梯構成的跨層環路與返程捷徑。
- [ ] 處理樓梯碰撞、步高或斜坡碰撞代理、平台接縫與護欄，確保正式玩家能連續上下樓且不必每階跳躍。
- [ ] 烘焙或連接各高度的可行走導航，處理樓梯與平台；若使用導航連結，必須對應角色實際能完成的通行，不可讓導航跨越實體樓板。
- [ ] 樓梯和高處平台的家具、物資與敵人點需有可靠支撐，避開踏步動線、孔洞和樓板內部。

驗收：

- 同 seed 可重現相同三維布局，總房數維持 50–100；跨層房不因占用多層而重複計數。
- 多 seed 測試不存在三維重疊、挑高空間被填滿、懸空門、階梯頂頭或孤立樓層。
- 正式玩家能由入口連續上樓、進入上層房間、經另一條跨層路線下樓並返回；攜帶大型物品時也能通過規定的搬運路線。
- 殭屍能使用同一樓梯尋路，跨樓層偵測及攻擊受到實際視線與通行條件限制；不能穿樓板、直接跳層或卡在平台接縫。
- 每個重要目標有有效抵達與撤退路徑；返程輔助能分辨樓層與上下樓方向。
- 離開重返後房間高度、物資位置、敵人狀態、探索紀錄與跨層捷徑狀態保持一致。

依賴：先與 POI-09 一起確定房間／接口的三維契約，再擴充 POI-02 的房型。POI-01、03～05 的目標、返程、搬運與敵人配置都須依實際跨層路徑工作；效能與保存分別由 POI-07、08 延伸驗收。

## 3. 建議實作批次

### 第一批：維修站探索內容第二版

建議先做 POI-09 與 POI-10 的三維資料／接口契約及樓梯通行原型，再整合 POI-01～04。跨層導航與必要的敵人通行檢查在這一批完成，不延後到內容全部鋪設之後：

- 8–12 種房型，包含樓梯與跨層房；先驗證 2–3 層，維持整個副本 50–100 間總房數。
- 可從入口上樓、跨房探索、再經合法路線下樓返回；布局包含跨層連通與環路。
- 三個可辨識區域、一個深處目標、一條可開通的返程捷徑。
- 可辨識樓層的基本探索紀錄，及依實際路程分配的物資。
- 同局保存新增的目標、探索、門與捷徑狀態。

完成條件：實際從停車處進入、搜刮、上下樓深入目標、選擇撤退、跨層搬回物資，再重返，整個流程可玩且狀態正確。推車等搬運工具先保留為評估項目。

### 第二批：危險、停靠與執行品質

完成 POI-05～07：改善跨層敵人配置與應對、停車支道和地形安置，進行多樓層效能量測與必要最佳化，補齊載入失敗及返程異常復原。若第一批已遇到卡死或明顯效能阻塞，相關項目提前修正。

### 第三批：跨局存檔與外部回訪

在副本身分和互動狀態規格較穩定後完成 POI-08，並把其他 POI 類型接入同一內容製作與保存流程。

## 4. 驗證與接續工作方式

討論時已有拓樸連通、導航、主場景進出與同局狀態測試；實機曾完成 96 房副本的入口、連接走廊與返程回放。這不等於完整探索所有房間或大型群體實戰已驗收。

後續每批應依變更補充：

- 多 seed 的房型、三維占用、跨層拓樸、入口返回與特殊目標可達性驗證。
- 正式玩家與敵人在不同尺寸、家具、門、樓梯、平台和跨層捷徑之間的物理／導航測試。
- 重返及存檔的物品、死亡、目標與互動狀態測試。
- 完整上下樓搜刮一趟的實機體驗，與 100 房總量、多樓層的長時間效能／群體敵人測試。

開始下一輪前：

1. 讀本計畫、根目錄 GDD／architecture，以及當下程式與 Git 狀態。
2. 對照 `world/instances/`、`world/poi_kit/`、`world/poi_config.gd`、`world/poi_spawner.gd` 與 `tests/test_poi_instances.gd` 確認基礎。
3. 選定批次，先將該批待選方案收斂為具體規格，再進行實作。
4. 完成驗收後更新本檔勾選狀態和現況文件；未完成提案繼續留在本計畫，不標成遊戲已有功能。
