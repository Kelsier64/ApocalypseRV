# 車內調度喇叭

**進度。** 設計已定案，尚未實作。

RV 上不放民用收音機，改放網路配發、固定在駕駛室的調度喇叭：主管在車上的聲音從這裡出來，面板上的訊號表顯示 RV 離網路照顧得到的範圍有多遠。設定意圖見 [GDD 世界觀](../../GDD.md#世界觀)。

## 為什麼不用收音機

- 收音機會讓玩家想轉台、預期聽到音樂，削弱「聽到旋律就一定是巨人」的保證（[GDD 第 8 節](../../GDD.md#section-8)）。
- RV 是網路配給的，主管的聲音應該從網路自己的硬體傳出來，不是前任車主留下的家電。
- 跟 Slender Speaker 同一種喇叭，等於在車頂放一顆巨人頭上那顆的小型版本。這接上「Speaker 原本是網路的警報喇叭」的暗示，但遊戲內不說破。

## 已確認的設計決定

| 題目 | 決定 |
|---|---|
| 裝置 | 網路制式的擴音喇叭罩，配訊號表、音量旋鈕與一支掛著的發話筒。沒有選台旋鈕、沒有頻道（2026-11-25） |
| 音量 | 旋鈕可以轉到關。關掉就聽不到廣播，期間的廣播不會補播（2026-11-25） |
| 發話筒 | 要做。按下發話只會收到機器自動回覆「本線路僅供接收」，網路仍然聽不到玩家（2026-11-25） |
| 範圍 | 只做裝置本體。廣播內容沿用短波收音機現有的音檔與排程；訊號表先接現有的偏離路線壓力，中繼站做好之後再換訊號來源（2026-11-25） |
| 音樂 | 這台裝置永遠不播旋律或音樂 |

## 代為決定、可以否決的項目

- **吃車上的電。** 開著時有很小的耗電，比一條車內燈條少。沒電就安靜，指針歸零。這讓「停多久」與電池狀況也影響能不能收到網路。
- **新車預裝一台。** 開局的 RV 與 `new_rv` 都在前牆上方、擋風玻璃正上方偏右預裝一台，駕駛視角看得到訊號表。它跟車內燈條一樣是可拆裝的物品，可以搬去別處，也能在合成站重做。
- **走 `Voice` bus**，跟短波收音機一樣，不依位置分配到 `Cabin`。音量和可聽距離都比手持收音機大，車門開著時在車外附近隱約聽得到。
- **音量四段**：關、低、中、高，新車預設中。對喇叭按 E 依序切換。關掉沿用物品既有的 `enabled` 並隨檢查點保存；低、中、高不保存，讀檔後回到中。
- **訊號弱時不補播**：訊號低於門檻時不開始新的廣播，播到一半的廣播會被雜訊蓋掉、淡出。

## 設計

### 1. 裝置與擺放

- 新物品 `Dispatch Speaker`，繼承 `Item`，跟 [cabin_light_strip.gd](../../equipment/cabin_light_strip.gd) 一樣是可拆裝的車上設備：固定在車上並接通本車才工作，長按 F 拆下，依附的牆板被打掉就停機掉落。
- 預裝：在 [starter_rv.tscn](../../rv/starter_rv.tscn) 與 [new_rv.tscn](../../rv/new_rv.tscn) 以 `initial_support` 掛在前牆結構槽，位置參考兩條車內燈條的寫法。
- 外觀分成三塊：喇叭罩（主要聲源）、一塊有指針錶和一顆琥珀色電源燈的小面板、面板側邊掛鉤上的捲線發話筒。

### 2. 開關與音量

- 對喇叭本體按 E：關 → 低 → 中 → 高 → 關，每段有旋鈕喀聲。提示文字走畫面 UI，用英文，例如 `Speaker: Low`、`Speaker off`。
- 三段音量的 dB 值放在場景或定義資源裡，不寫在程式常數裡。
- 關掉時：停止播放與排程、電源燈熄滅、指針歸零、不耗電。

### 3. 廣播播放

- 沿用短波收音機的音檔（[shortwave_radio.tscn](../../props/shortwave_radio.tscn) 的 `transmissions`）與排程規則：開機後等 `FIRST_SIGNAL_DELAY`，每段之間等 `SIGNAL_GAP`，相鄰兩段不重複。
- 把 [shortwave_radio.gd](../../props/shortwave_radio.gd) 裡的排程抽成共用元件，例如 `BroadcastSchedule`，兩台裝置共用。抽出後短波收音機的行為完全不變。
- 亂數用元件自己的 `RandomNumberGenerator`，不讀寫玩法或世界生成的亂數（見[音效系統](audio-overhaul.md)的亂數規則）。
- 訊號強度 `s`（0 到 1，見下一節）影響播放：
  - `s` 高：廣播清楚。
  - `s` 中：廣播偶爾斷續，人聲音量隨機掉下去，雜訊層按 `1 - s` 混進來。
  - `s` 低於門檻：不開始新的廣播；正在播的廣播被雜訊蓋過並淡出。
  - `s` 為 0：只剩微弱的雜訊底噪，或完全安靜，以試聽決定。
- 門檻與斷續的參數放在場景或資源裡，數值以試聽為準。

### 4. 訊號表與涵蓋

- 訊號來源是 [deviation_pressure.gd](../../world/deviation_pressure.gd)，現階段代表「離公路走廊多遠」，中繼站做好後換成中繼站涵蓋。裝置只透過一個入口讀取訊號，之後換來源時裝置不用改：
  - `DeviationPressure.signal_strength_at(point: Vector3) -> float`：用 `RoutePressureSample.sample(field, point)` 取裝置所在位置的樣本，配合 `state.highwater` 算出往回開的距離。
- 計算方式要跟起霧的判定一致，讓指針先掉、霧後起：
  - 把 [route_pressure_state.gd](../../world/route_pressure_state.gd) `advance()` 裡寫死的 120、80、100、70 改成具名常數（往回開的開始與安全距離、離林的開始與安全距離），訊號與起霧都讀這些常數。
  - 往回開與離林兩軸各自算：在安全距離內為 1，到開始距離為 0，中間線性。`s` 取兩軸的較小值；樣本 `exempt` 時為 1。
  - 結果：玩家開始偏離時，指針會在起霧前就往下掉，可以當成預警。
- 取樣頻率每秒兩次就夠，指針用平滑追蹤，並依 `1 - s` 加上抖動。
- 用裝置自己的位置取樣，不用玩家的位置：玩家下車走遠，車上的訊號不會跟著掉。
- 訊號強度不存檔，讀檔後重新取樣。

### 5. 發話筒

- 對發話筒按 E：拿起話筒的聲音、按鍵喀聲，接著從喇叭播出一段機器回覆，例如 `This line is receive only.`，另做一段 `Transmission not authorized.` 輪流使用。
- 回覆會切掉正在播的廣播，之後照常排下一段。回覆播放時再按只有按鍵喀聲。
- 喇叭關掉、沒電或損壞時，按下只有喀聲，沒有回覆。
- 回覆不受訊號強度影響：這是車上這台機器自己的拒絕，不是網路的回應。
- 互動目標：[player_interact.gd](../../player/player_interact.gd) 對帶有 `interact` 方法的非 Item 物件也能按 E，話筒可以先試做成這種子物件；如果射線只會解析到上層的 Item，就改在 `DispatchSpeaker.interact` 裡依瞄準點離話筒或喇叭較近來分流。

### 6. 電力、損壞與維修

- 耗電走 [vehicle_energy.gd](../../rv/vehicle_energy.gd) 既有的 `step_work(delta)` 路徑：開著時每秒耗一點電，初值約 0.01，比一條車內燈條的 `cabin_light_draw` 少。電不夠就跟 `can_operate()` 為假一樣處理：安靜、燈熄、指針歸零。
- 損壞、維修、怪物攻擊資格與歸零刪除，都沿用一般設備的規則（[RV 系統](../systems/rv.md#損壞維修與爆胎)）。
- 合成站新增配方，材料與時間參照短波收音機的配方（[recipe_catalog.gd](../../equipment/recipe_catalog.gd)）。
- 在 [save_scene_catalog.gd](../../core/save_scene_catalog.gd) 登錄新場景（CLAUDE.md 硬規則 3）。

### 7. 平板與名稱

- 平板 Equipment 頁列出這台裝置，狀態文字用英文：`Receiving`、`Weak signal`、`No signal`、`Off`、`No power: disabled, removed or damaged`。寫法參照 `CabinLightStrip.get_status()`。
- 在 [rv_terminal_presenter.gd](../../equipment/rv_terminal_presenter.gd) 加顯示名稱，在 [inventory_item_icons.gd](../../core/inventory_item_icons.gd) 加圖示。

### 8. 美術與聲音素材

- **模型**：先用素模把互動、擺放與聲音做完。正式模型照 `apocalypse-rv-3d-scenes` skill 的流程另做：冷戰時期的類比設備、漆面金屬、喇叭罩的造型語言跟 Slender Speaker 頭上的喇叭一致。
- **世界內文字**：錶面只畫刻度與色區，不寫 `SIGNAL`、`VOLUME` 這類提示字；可以有一塊製造銘牌（CLAUDE.md 硬規則 1）。
- **聲音**：放在 `assets/audio/dispatch_speaker/`，附 README 記錄來源與做法：
  - 雜訊迴圈：優先找 CC0 錄音，找不到就用腳本離線生成帶限雜訊與劈啪聲。
  - 旋鈕喀聲、拿起與掛回話筒、按鍵喀聲：CC0 錄音。
  - 機器回覆：主管語音的製作方式還沒決定（[GDD 第 9 節](../../GDD.md#section-9)），先做暫代版本，要求一個字一個字拼出來、音高平板、帶廣播頻段的質感，跟現有的短波人聲同一路處理。主管語音定案後換掉。
- 規格與事件檔照[音效系統](audio-overhaul.md)的素材規格；一次性聲音做成 `assets/audio/events/dispatch_speaker/` 下的 `SoundEvent`。

## 不做的事

- 主管的廣播內容系統、電台識別音、三層聲音，以及中繼站涵蓋（見 GDD 的[世界觀待決定提案](../../GDD.md#世界觀的待決定提案)）。
- 手持短波收音機不改：它不接訊號強度，外觀也不改。之後要讓兩台共用訊號與外觀語言，另開工作。
- 不新增存檔欄位，也不為了這台裝置擴充檢查點（CLAUDE.md 硬規則 3）。

## 測試

新增 `tests/test_dispatch_speaker.gd`，數值一律從場景或資源讀取，不寫死（CLAUDE.md 硬規則 5）：

- 訊號計算：安全距離內為 1、超過開始距離為 0、中間單調遞減；`exempt` 為 1；兩軸取較小值；起霧判定與訊號讀同一組常數。
- 開關與音量：四段依序切換，三段音量依序變大；關掉時不播放、不排程、不耗電。
- 電力：沒電時安靜、`get_status()` 回報缺電；補電後恢復原本的開關狀態。
- 發話筒：開著且有電時播出回覆並切掉廣播；關掉、沒電或損壞時沒有回覆。
- 預裝：`starter_rv` 與 `new_rv` 各有一台掛在前牆；`SaveSceneCatalog` 與配方表都有登錄。
- 拆下、牆板毀壞或裝置毀壞時聲音停止。
- 播放與訊號取樣不改變世界生成與遭遇用的亂數狀態。

共用排程抽出後，[test_item_player.gd](../../tests/test_item_player.gd) 裡的短波收音機測試要照常通過。最後跑一次完整的 `scripts/test.ps1`。

## 試玩場景與人工驗收

照 `godot-playgrounds` skill 做一個試玩場景：RV 停在公路上，駕駛座可以直接開。Esc 選單的 Playground 分頁放測試用控制：

- 立刻播下一段廣播。
- 用滑桿強制指定訊號強度，或恢復讀取實際訊號。
- 把 RV 傳到公路外、樹林邊或往回開的位置。
- 把電池放空、補滿。

交給使用者的檢查清單：

- 從駕駛座看得清楚訊號表，指針的抖動不惱人。
- 四段音量聽得出差別；高檔不會蓋掉引擎與 Slender Speaker 的預警方向。
- 開離公路時，指針在起霧前就往下掉；訊號弱時的斷續聽起來像訊號不好，不像音檔壞掉。
- 發話筒的回覆好不好笑，機器感夠不夠。
- 開門、關門時在車外聽到的音量合不合理。
