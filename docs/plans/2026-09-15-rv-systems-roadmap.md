## 1. 目標與已確認方向

讓 RV 成為可長期維持、調整配置的移動基地。玩家能理解車輛和設備為什麼可以運作、為什麼停機，以及如何透過搜刮、換電池、加油和維修恢復功能。

### 1.1 使用者已確認的能源設計

1. **發電機是設備；電池是道具。** 電池走實體道具的取得、搬運、背包與更換流程，不做成用 F 自由貼面放置的 Equipment。
2. 車子行駛時，已安裝且正常的發電機發電，電力存進電池。
3. 停車熄火時不發電，由電池供電，電量逐漸消耗。
4. 缺電時，玩家可以更換有電的電池，或發動引擎耗油發電，為電池充電。
5. 「停車不發電」指停車熄火的常態；**停在原地但引擎已發動，是耗油充電的例外**。不能只用車速是否大於零判斷發電。
6. 發電機必須屬於該車且可運作；引擎運轉本身不能繞過發電機設備，直接替電池增加電量。

這些規則取代前次建議中「電池也是設備模組」和現有「發電機只要連車便自動燒油補電」的方向。後續不得把電池默默改回設備，或在車內保留另一份獨立、無來源的永久電量。

### 1.2 保留原則

- 保留底盤、輪槽、可安裝設備、單車材料庫與移動 RV 攀爬支撐的既有基礎，逐步拆分責任。
- 延續「車體上除底盤與輪胎外，其餘功能與結構可設備化」的方向；可更換電池是使用者明確指定的道具例外。
- 車板、駕駛座、發電機、平板、分解機、合成站，以及後續油箱與材料儲存模組，可以使用共用設備契約。
- 每台 RV 的材料、電池、燃油、設備與工作互相隔離；不以全域第一台車或第一台設備代替實際歸屬。
- 結構板可用接點協助對齊；一般設備保留自由貼面配置。先補安裝合法性，不直接把全部玩法改成固定格子。
- 平板負責顯示與操作，資源交易和生產規則由系統處理。
- 設備越多應有空間、重量、能源或維護成本，讓升級與配置產生可理解的取捨。

### 1.3 第一輪不必同時完成的項目

多人同步、複雜接線網路、引擎熱力學、電池化學模擬與完整車輛模擬不列為本輪前置條件。手排多檔位、防禦、監控及更多升級設備保留方向，但要在共同規則與基本駕駛穩定後擴充。

## 3. 建議架構與狀態所有權

以下名稱為職責提案，實作時可依 Godot 場景整合調整；不要求一次建立全部類別。底盤保留相容入口，逐批把內部工作交給專責系統，避免同時改壞所有呼叫端。

| 部分 | 擁有的規則／資料 | 不應承擔的工作 |
|---|---|---|
| 車輛根／Chassis | 車輛 ID、物理本體、各系統入口 | 配方 UI、每一種設備的特殊流程 |
| VehicleController | 引擎狀態、檔位、油門、煞車、轉向、駕駛權限 | 直接憑輸入增加電量 |
| EquipmentRegistry／MountSystem | 該車設備清單、安裝／拆卸、支撐關係、掛載事件 | 用每影格全域群組搜尋替代登錄 |
| EnergySystem | 本車能源調度、燃油存取、已接入電池、充放電與耗能結果 | 另存一份與電池無關的永久 current_power |
| BatteryItemState／BatterySocket | 電池實例電量與容量／車上電池插槽的持有關係 | 把電池變成自由放置的 Equipment |
| MaterialStorage | 材料數量、容量、預留與提交 | 載入 UI 或物品模型 |
| ProductionSystem | 配方、工作、輸入所有權、資源交易、出料 | 依賴平板是否開啟才能運作 |
| Equipment | 外觀、互動、耐久、安裝狀態、功能元件 | 各自重寫完整連線、取消及毀損機制 |
| 平板／儀表 | 呈現狀態、可用操作、錯誤原因 | 自行扣材料、扣電、創建成品 |
| Snapshot／Save 層 | 保存、還原、版本、ID 關係 | 以當次 Node instance ID 當永久身分 |

### 3.1 資料定義

- `EquipmentDefinition`：穩定類型 ID、名稱、場景、重量、耐久、安裝限制、功能與耗能參數。
- `RecipeDefinition`：ID、材料成本、電力需求、處理時間、工作站能力需求、輸出場景及數量。
- `BatteryDefinition`：道具類型、額定容量、重量與可相容插槽；是否大型物品屬待定平衡項。
- `BatteryItemState`：實例 ID、定義 ID、剩餘電量；若後續做電池耐久／容量衰退，再加入對應欄位及版本。
- `InstalledEquipmentState`：實例 ID、車輛 ID、支撐 ID／接點、本地變換、耐久、開關和設備專屬狀態。
- `ProductionJobState`：工作 ID、配方、輸入／預留資源、進度、工作站、待出料結果。
- 類型定義可以共用，但運行中電量、耐久和工作進度必須屬於個別實例，不能修改共用 Resource 而影響所有同型物件。
- 沿用並逐步強化 [core 契約](../../core/rv_connection.gd)、[群組](../../core/groups.gd)、[WorldEntities](../../core/world_entities.gd)，避免 Equipment／Chassis 互相預載造成循環。

### 3.2 生命週期

把安裝狀態與運作狀態分開，避免一個 enum 包含所有組合：

- 安裝：世界中、搬移預覽、已安裝、正在拆卸、已移除。
- 運作：關閉、待機、工作中、缺電／缺油暫停、故障、毀損。
- 共用入口：檢查安裝、安裝成功、準備拆卸、開始搬移、取消還原、供能改變、毀損、離開場景。
- 一般設備只有在安裝完成、仍屬本車、耐久可用且開關允許時才可工作；各功能再檢查能源與輸入。
- 搬移快照須包含原父節點／本地變換、碰撞層與遮罩、freeze／freeze_mode、速度、材質與必要工作狀態。取消不能把原本自由剛體永久黏在空中。
- 原支撐已消失、玩家死亡、設備被毀或場景卸載時，要安全結束操作，清除快取、UI、座位、碰撞例外與工作持有關係；重複清理不得重複出料。

### 3.3 安裝與支撐

- 車輛歸屬與安裝支撐分開記錄；場景父子階層可以用來同步移動，但不作為全部業務狀態。
- 支援指定安裝面、允許的朝向、佔用體積、必要的進出料與玩家通行空間。
- 預覽與確認使用同一驗證規則，確認時重新檢查 RV／支撐是否仍有效及是否重疊。
- 禁止附著在 Prop、怪物和其他未授權目標；避免設備成為自己的祖先或形成支撐循環。
- 建議支撐破壞時，依附設備先停止服務、解除登錄，再作為世界物體掉落；實際掉落是否造成額外損傷屬後續平衡。
- 掉落採支撐位置的車輛線速度與旋轉貢獻，驗證不殘留跟車補償。不得把角色的 RVSupport 與設備支撐資料混為同一份狀態。

## 4. 引擎、發電機與電池完整規則

### 4.1 行為表

| 情境 | 發電 | 電池與用電 | 燃油 |
|---|---|---|---|
| 引擎運轉、車輛行駛、發電機正常 | 發電並儲入接入電池 | 用電設備消耗電量；淨變化依供需而定 | 行駛消耗，納入發電負載規則 |
| 停車熄火 | 不發電 | 待機與開啟設備逐漸耗電 | 不因發電而耗油 |
| 原地發動引擎充電 | 正常發電機可以發電 | 有剩餘容量則充電；負載過高可能無法淨充電 | 持續怠速耗油，不能免費充電 |
| 熄火滑行、下坡或被外力推動 | 不發電 | 仍由電池供電 | 不因車速而自動耗發電燃油 |
| 引擎運轉，但發電機未安裝／關閉／搬移／毀損 | 不發電 | 消耗既有電池電量 | 引擎按自身運轉狀態耗油 |
| 油料耗盡 | 引擎停止後不再發電 | 電池有電仍可供非引擎設備使用 | 不出現負油量 |
| 電池已滿 | 不再增加電量 | 有負載時可再次接收發電；遵守容量上限 | 引擎仍運轉就仍有引擎耗油 |
| 電池耗盡、引擎熄火 | 不發電 | 用電工作暫停，保留進度／輸入 | 換電池或啟動引擎恢復 |

「停車慢慢耗電」應有可辨識的待機負載，不把不明原因扣電藏在底盤控制程式。各負載的數值可調，是否提供總電源切斷及切斷後是否仍有少量耗電，列入待定事項。

### 4.2 引擎與耗油

- 引擎狀態至少分熄火、運轉、故障；啟動過程是否獨立狀態依玩法需要補充。
- 車速、駕駛是否入座與引擎是否運轉是不同資訊。離座不應意外把已選擇的原地充電取消；離座時的停車安全由手煞車／車輛控制處理。
- 燃油由單一調度入口記帳。建議分怠速、行駛負載、發電附加負載三項，具體公式和數值待實測；不能保留舊底盤扣油與發電機扣油，再額外重複扣同一份成本。
- 沒有引擎運轉或有效發電機時，禁止任何「有油門就加電」的舊路徑。
- **啟動引擎是否需要電池電力尚未由使用者指定。** 第一版建議允許空電池時手動啟動引擎，確保「電池耗盡 → 發動耗油充電」可用。若日後改成電力啟動，必須同時提供跳電、手搖或更換電池等明確救援流程。

### 4.3 電池是有狀態的實體道具

- 建議第一版為一個可互動電池插槽。插槽是車輛／載具介面，電池本身仍是 Prop 類道具；多插槽與並聯容量後續再擴充。
- 放在地上、背包或車內地板上的電池，不會因靠近 RV 就自動連上供電。必須透過插槽安裝操作接入。
- 電池剩餘電量在拾取、手持預覽、丟棄、插入、取出、換車、POI 重返及存檔後完全保留。
- 手持外觀只讀取道具狀態，不另建立一份會獨立充放電的電池；同一實例同一時間只能由世界、背包或插槽中的一處持有。
- 更換必須是完整交易：先確認新電池可用及舊電池去處，再一次完成交換。背包無空間時可採原槽位交換；若改為落地，須先確定安全有效的生成位置。
- 交換失敗不消耗新電池、不刪舊電池、不重置任一電量。電池插槽的機械互動不能依賴平板有電才能使用。
- 第一版建議無電池時不提供一般車載用電；引擎可以依啟動規則運轉，但發電機沒有可儲能目標，不累積隱藏電量。無電池直接供電為待選擴充，不視為已確認需求。
- 電池大小、容量等級、重量、取得來源、回收產出與能否製作集中在資料中；不能沿用未設定物品的 Unknown Material fallback 作正式平衡。

### 4.4 發電機與能源調度

- 發電機保留設備的安裝、耐久、開關、故障與拆卸流程；引擎運轉是它的發電前提。
- 發電機開關只控制發電功能，不自行在熄火時偷啟動引擎。前次提到的自動補電門檻只能用於已運轉引擎下的充電控制。
- 若提供低油量保留設定，需區分「停止額外發電負載」與「停止怠速引擎」，並明示結果；禁止無提示自動切斷行駛。
- 用同一模擬步統計發電供給與設備需求，使用固定的分配／暫停規則，避免節點順序與 `_process`／`_physics_process` 混用決定誰搶到最後的電。
- 生產必須支付完整操作成本或明確的分步成本。建議持續工作逐步支付，瞬間出料採完整交易；不足時不產出免費進度。
- 充放電需受容量與非負限制。滿電不溢出、缺油最後一步不免費發電，發電少於負載時電量正確下降。
- 顯示電池目前／最大電量、充放電方向、發電量、總負載與停機原因。電量單位及數值先集中設定，不宣稱為實際 kWh。

## 5. 材料、生產、維修與駕駛細節

### 5.1 材料與生產

- 配方與設備定義資料化，平板只送出工作要求，服務回傳成功或具體失敗原因。
- 即時製作先檢查材料、完整電費、同車工作站、輸出資源及出料位置，再原子提交；生成或提交失敗完整回復，不重複退款。
- 佇列工作明確選擇材料何時預留／扣除；取消時區分未消耗預留與已完成工作，規則對玩家可見。
- 分解機第一版建議一個處理槽加有限佇列；若採多槽，每槽成本或整機吞吐上限必須明定，不能投入越多就免費同時處理。
- 進料由工作站持有，跟隨機器位置；缺電暫停，拆卸／毀損安全退料或保留明確可取回的輸入。
- 成品有安全出料空間並繼承適當車輛速度；出口堵住時保存待出料成品，不再次扣材料，也不無限生成重疊物體。
- 材料庫加入容量前先定義單位；儲存設備拆除／毀損時的溢出、材料取回及遷移規則必須先完成，不能直接截斷數字。
- 加油、輪胎拆裝、電池交換沿用一致的成功／失敗回傳與所有權轉移原則。

### 5.2 駕駛、損傷與維修

- 建立明確引擎啟停、前進／空檔／倒車與獨立手煞車；駕駛 Space 不再同時當煞車與倒車。
- 手排多檔位列為後續駕駛完善項，等基本操作穩定後加入檔位比、換檔與引擎表現。
- 底盤毀損、無油或其他阻止驅動的狀態，由同一入口檢查；正式遊戲停用方向鍵遙控，測試場透過正式控制 API 輸入。
- 區分「可修復故障」「設備摧毀需更換」「底盤報廢」。永久報廢／Game Over 尚未定案，不能在修正驅動 gate 時順便替玩家決定結局。
- 維修須有目標、所需材料、耗時、可修到的上限、進度與中斷規則；生命歸零是否留下殘骸依設備類型定義。
- 各輪槽保存輪胎狀態，明確選擇安裝槽位；拆裝和修理在行駛中的限制需定義。損傷影響轉向／抓地／驅動的數值須可控、可顯示。
- 座位被毀、駕駛死亡或車輛失效時恢復玩家碰撞、相機與控制；下車點需通過正式玩家體積的通行驗證。

### 5.3 重量與碰撞

- 整車重量計算納入安裝設備、接入電池及後續明確建模的貨物；先避免同一物品被重複計重。
- 依設備位置計算重心，規定重量更新時機；驗證加裝屋頂重物、左右偏載、拆除設備後的變化。
- 以正式底盤與輪胎驗證坡道、煞停、倒車、轉彎、側撞、翻車與大型外掛。
- 目前凍結設備碰撞是否需要合併為車體碰撞或使用其他掛載表示，先建立最小實測場景再決定。不能只因增加重量計算就宣稱外掛碰撞已正確。
- 保留牆面攀爬、屋頂支撐與怪物拆板契約；若碰撞表示改變，精確支撐面辨識也須同步驗證。

### 5.4 儀表與平板

- 駕駛儀表：速度、檔位、手煞車、引擎狀態、油量、電池電量、充電指示與重要故障。
- 平板：本車設備清單、開關、耐久、耗電明細、工作進度、材料／配方、故障與無法操作原因。
- 電量、材料、工作站安裝／拆除等改變時，即時更新按鈕可用性，不能只更新數字或等下次開畫面。
- 區分「沒有電池」「電池沒電」「沒有發電機」「引擎未啟動」「出料口堵住」；提示應協助玩家採取下一步。
- 不依賴有電的平板才能換電池、加油或執行必要的救援操作。

### 8.1 本次採用的具體規則

- 單插槽；普通／大容量電池 100／200、重量 15／30。製作為空電池，拾取、交換和保存保留 ID／電量。
- 空電池／無電池可以手動點火；無電池不供一般用電。電池更換限車速 ≤ 0.5 m/s，單次同步提交，不會在交換中間推進工作。
- 引擎每秒油耗 0.04＋0.9×油門負載；發電最多另耗 0.6 油、產 1.8 電；待機每秒 0.15 電。充電預設 80% 門檻與 5 油保留，可在平板調整，保留油設定不會停止引擎。
- 4 個前進檔、空檔、倒檔及獨立手煞車已完成，離合器／引擎轉速未納入首版。
- 每輪保存耐久，接地行駛每公尺磨耗 0.002 HP。維修／輪胎拆裝要求熄火停穩；2 秒、2 Metal Parts 修 60 HP，中斷不扣款。
- 底盤歸零失效但可修；油箱／材料架歸零留殘骸，普通設備歸零刪除。油箱保留自身燃油；拆材料架只減容量，超額存量保留可領出。
- 分解機 1 個處理槽、最多 4 個輸入；合成站佇列 4。排隊預留材料，取消退材料但不退已用電，出口堵塞保留工作。
- F6/F9 提供版本 1 室外檢查點，包含世界範圍、玩家、車輛、設備、動態物件、工作和已訪 POI；不支援副本內直接保存、多槽與舊版本遷移。
- 能源／材料／保存已分離；控制、輪槽、登錄暫留 Chassis，不為職責表每列強制建立額外類別。

### 8.2 後續仍需驗收

- 長途經濟：多種油門、工作負載、停車搜刮時間、敵人壓力下的燃油／材料供需；固定 5 km 且關閉油耗的物理回放不作經濟證據。
- 極端物理：屋頂重載、左右偏載、側撞、翻車、大型外掛與怪物群。重量／重心已做，凍結設備對底盤的外力傳遞仍是架構限制。
- 安裝體積／操作空間已由共同驗證器處理，傾斜車身和複雜支撐連鎖需更多實機配置；下車極端受困情境仍需補測。
- 電池老化、多插槽、引擎聲引敵、多人與更多內容保留原先後續方向。

## 9. 接續開發方式

1. 先讀本計畫、根目錄現況文件、AGENTS.md 與當下 Git 差異，核對是否已有功能完成。
2. 按批次選取工作，先寫清該批的狀態轉移、失敗結果及驗收情境，再修改程式。
3. 首先保護資源所有權、玩家控制與設備清理；新設備內容建立在共同契約上。
4. 本車對外介面逐批遷移，刪除舊發電捷徑時檢查所有呼叫端及測試設定，避免兩套能源同時記帳。
5. 完成驗收後才勾選工作並同步 GDD／architecture／README；本計畫中的提案不得提前寫成目前功能。
6. 保留原始 `todo`、使用者對 `todo_for_ai` 的未提交修改及歷史文件。與 [POI 計畫](2026-09-15-poi-roadmap.md) 共用道具狀態與保存契約，避免兩邊各做一套。
