# 世界生成重構

[計畫總覽](README.md) · [世界系統](../systems/world.md) · [環境系統](../systems/environment.md) · [遊戲設計](../../GDD.md#section-9)

讓每一局、每一段路都不一樣：公路、地形、河谷與橋由一份依種子排出的旅程編排決定，生態再從地形形狀裡拆出來，讓同一種地形能長出不同的森林，也能有不是草地的樹林，例如沙地上幾乎全是枯樹。施工在 worktree `claude/world-generation-overhaul` 進行，分階段審查後以 PR 合回 main。

## 問題

**世界由固定週期組成，種子只平移相位。**

| 內容 | 現在的生成方式 | 位置 |
|---|---|---|
| 彎道 | 兩個正弦相加，主週期約 530 m | [TerrainRoute.x](../../world/terrain/terrain_route.gd) |
| 升降 | 一個正弦，約 6 km 一循環 | `TerrainRoute._vertical_slope` |
| 路寬 | 兩個正弦 | `TerrainRoute.width` |
| 路旁土堤 | 每 215 m 起伏一次 | `TerrainLandforms._height_v14` |
| 地形 | 每 `REGION_LENGTH` 換一種，順序固定 | `TerrainLandforms.appearance_at` |
| 河川 | 每 `REGION_LENGTH` 一條，位置在每段地形的同一處 | `TerrainLandforms.river` |
| 乾谷 | 每 `DRY_VALLEY_INTERVAL` 一個 | `TerrainLandforms.dry_valley` |
| 停靠點 | 每 `stop_spacing` 一個，三個一循環 | `WorldField.stop` |

**地形是沿公路掃出的剖面。** 每種地形的高度都用「離公路多遠」定義：懸崖牆永遠平行公路，峽谷台階以公路為中心對稱，山脊騎在公路上。上坡在哪一側、懸崖在哪一側，整個世界只由 `offset` 的奇偶決定一次。

**橋沒事就出現。** 公路高度先由正弦決定，地形再被拉向路面。每條河都被壓到路面下至少 8 m，所以每條河都是橋；每個乾谷也故意切深，另外路面離地超過 4.5 m 就自動變高架（`TerrainLandforms._structure_cell`）。結果是固定間隔就有一座橋。

**生態綁在地形編號上。**

- 一個 landform 編號同時決定高度、地面顏色、濕度、樹種、樹密度、地被、粉塵、霧和風的遮蔽，表格都在 [TerrainLandforms](../../world/terrain/terrain_landforms.gd)。編號只沿公路方向變化，橫向沒有差別。
- 每種地形的樹種組合寫死在 `tree_choice`，真正茂密的只有 basin。
- [ForestMeshes](../../world/terrain/forest_meshes.gd) 的 8 個編號實際只有 3 種樹形：0–3 是同一種針葉樹換葉色，4–5 是拔掉葉子的同一棵樹，6–7 是兩棵相近的闊葉樹。每個編號只有一個網格，沒有逐棵色差。
- [ForestScenery](../../world/terrain/forest_scenery.gd) 用抖動網格擺樹，再用一層叢集噪聲疏密化，沒有林緣、空地、樹下灌木與年齡層。
- 地表 shader 只有一張土壤貼圖加頂點色（[terrain_v14.gdshader](../../world/terrain/terrain_v14.gdshader)），沒有沙、灰燼這類材質。

**取樣成本與結構。**

- [WorldField.surface](../../world/terrain/world_field.gd) 每取樣一點，都要做一次公路最近點迭代、掃附近場址、跑地表特徵與河道；`normal_at` 再呼叫 4 次。地面建好後有一份 [TerrainGrid](../../world/terrain/terrain_grid.gd)，散佈已經從它取樣，但森林仍在每個候選位置直接查 `surface` 與 `normal_at`。兩者結果不同：格網只要一個角落被保留就把整格視為保留，所以森林不能在同一生成版本裡直接換成格網。
- `surface` 裡寫著兩套開場避難所的整地函數，內容幾乎重複。
- [ChunkGenerator](../../world/chunk_generator.gd) 的地面顏色連續覆寫三次，只有最後一次有效；`region_weights` 的三區制每點照算卻沒人用。
- `seed_for` 把版本 16–20 對應回 15，各處另有寫死的版本覆寫。

**遠景沒有地標。** 可走範圍外只有同一剖面的延伸，沒有遠山或稜線，玩家沒有方位感。

## 已定案

- 公路、地形、河谷、橋與生態由同一份旅程編排決定，不再各自照固定週期出現。
- 地形順序依種子洗牌，不連續重複。
- 橋是少見的地標，只出現在章節安排的深谷或大河。公路可沿谷底下切通過，小溪用箱涵路堤。下切路段需要涉水時，水深須容許房車、步行與怪物導航通過。
- 生態是獨立於地形形狀的一層，生態區定義是資料資源，不寫死在程式表裡。
- 沙地枯木林起風時揚沙。粉塵改由土質與植被覆蓋決定，不再是「森林裡幾乎沒有沙塵」。
- 起霧時，沙地枯木林算 Slender Speaker 能出沒的森林。枯樹遮不住巨人，所以這是高風險區。每個生態區用資料旗標決定算不算。
- 森林樹木的倒樹紀錄只保留到本次遊玩結束。撞倒後即使開遠再折返，樹仍維持倒下狀態；F9 讀回檢查點時，森林依種子重建。此規則只適用於森林樹木。
- 開場避難所是固定入口，後續停靠點由章節安排。章節不替燃料預留場址，也不保證兩份燃料之間的距離。
- 公路分岔只做短支線：通往場址，或繞一小段後接回主路。不做兩條都能長途行駛的主線，所以單一主線的契約可以固定。
- 施工方式是 worktree 加 PR。

## 對外承諾

以下幾點施工後長期固定；章節長度、橋的頻率、格網解析度和生態混合比例都保留調整空間。

- 同一個種子、設定、生成版本和各亂數域版本，重建同一個基礎世界。
- 區塊載入順序不影響結果。直接查詢遠方的位置（例如讀取遠處的檢查點），結果和一路開過去相同。
- 每個場址、跨越物和樹都有唯一的歸屬。
- 畫面、碰撞和導航對同一個物件採用同一份幾何。

## 保留的契約與原則

- 公路是 `x = f(s), z = -s`，永遠往 -Z 前進、不折返；串流的 band 劃分依賴這一點。
- 整幅道路、路肩與路旁場址所需的空間，永遠留在可碰撞地形的側向範圍（`terrain_half_width`）內。現行正弦路線天生有界；樣條路線必須明確限制側移，不能逐段累積。
- 坡度、彎道半徑與路寬的上下限照 [WorldProfile](../../world/terrain/world_profile.gd)；起點的平直安全路段保留。
- `WorldField` 的查詢仍是種子與世界座標的純函數，與區塊載入順序無關。
- 視野以受限為主：近路的土丘、岩肩與低層植被先遮住側向遠景，彎道逐段揭露前路。晴天也要成立。開闊處是刻意安排的視窗，讓玩家在彎口看見遠方地標（例如中繼站的天線塔與紅燈），進林後失去視線，到下一個開口再判斷它在哪一側。
- 場址避開道路、河川與橋的引道，位置不合格就不放，不無限重抽。

## 架構

| 層 | 責任 | 取代 |
|---|---|---|
| 旅程編排 | 依種子排出一串章節。每章決定長度、地形、生態候選、路況（直路、大彎、連續急彎、爬坡、高原）、跨越物（河、深谷、無）與停靠點候選 | 各自的固定週期 |
| 路線 | 依章節的路況生成帶曲率與坡度上限的樣條，公路高度與地形一起規劃 | `TerrainRoute` 的正弦 |
| Landform | 世界座標的地形形狀：懸崖、山、谷是地上的東西，公路從旁邊或中間穿過；上坡的一側隨章節改變。提供生態偏好與上下限（濕地必濕、峽谷偏沙礫） | 以公路為軸的剖面、`TerrainLandforms` 的顏色與密度表 |
| 跨越物 | 章節安排的河與谷。依路面與水面、谷底的落差選箱涵路堤、下切過河或橋 | 固定間隔的河、乾谷與自動高架 |
| 共用格網 | 擴充既有的 `TerrainGrid`，地面、森林、散佈與導航都從格網讀 | 森林與其他讀取端各自重算 `surface` |
| 環境場 | 世界座標上的連續場：濕度、土質（壤土、沙、礫、泥炭、灰燼）、擾動（火燒、枯萎、伐木） | `WorldField.surface` 的 `moisture` 與 `material_weights` |
| 生態區 | `.tres` 資源：地表材質、地被層、樹種池與健康比例、林分型態、密度範圍、粉塵、霧、環境音標籤、Slender 旗標 | `TREE_DENSITY`、`GROUND_DENSITY`、`DUST_COLORS`、`tree_choice` 與 `ScatterCatalog` 的六格地形權重 |
| 林分 | 生態區內 80–250 m 的區塊，有自己的主次樹種、年齡、密度與型態（密叢、疏林、殘存人工林列、火燒、空地）；邊界是林緣 | 叢集噪聲 `clusters` |
| 單株樹 | 群聚式擺放（母樹與子樹），記錄樹種、變體、年齡、健康、傾斜、色調 | 抖動網格 |
| 遠景地標 | 可走範圍外的遠山與稜線，與章節的地形相符 | 同剖面延伸 |

開場避難所的整地移到它自己的場址模組，`surface` 只負責組合各層。

### 路線與跨越物的決定順序

1. 旅程編排排出章節。
2. 依章節先產生會影響道路的原始地形，包含谷底、水位、可落腳的兩岸與引道所需範圍，再列出跨越候選。這些資料在第 2 階段納入求解，第 3 階段擴展周圍地形與遠景。
3. 同一份道路規劃決定路面高度、兩端引道和跨越方式，在坡度、彎道半徑與側向範圍限制內接上相鄰章節。候選超出限制時，依固定順序嘗試移動跨越位置和改用符合章節條件的跨越方式。如果仍不可行，就捨棄會截斷主路的河谷候選，保留連續可行駛的道路。
4. 地形整地、橋面、碰撞與導航共用跨越規劃。箱涵路堤頂面可供車輛與步行通過。下切路段若經過水面，第 2 階段須定義房車、步行與怪物都能通過的最大水深，並由同一份規劃標明可通行的淺灘和應阻擋導航的河床。

### 場址排程與歸屬

開場避難所保留 `stop(0)` 的固定入口，供正式場景安置玩家、房車與教學。主要停靠點與加油站改由章節提供候選，小場址、越野場址與巨型避難所共用這份候選查詢來判定避讓。

道路與跨越物定案後，場址規劃以原始地形、道路和引道資料檢查占地。衝突判定涵蓋相鄰章節，並以固定優先順序取捨。章節候選以章節和槽位識別，跳過一處不會改變其他候選的身分或內容亂數。`WorldField.sites_near_z` 查詢通過檢查的場址，供整地、串流和其他讀取端使用。

### 遠距查詢與快取

章節按固定順序規劃，首次查詢遠方可能需要補算前面的章節。階段 0 選定固定種子與近、中、遠里程，從新程序或空章節快取量測 F9 讀到可操作的時間、準備期間最長的單幀停頓，以及抵達各里程的峰值規劃快取記憶體。用同一台機器和畫質記錄基準與各項上限。

第 2 階段須通過這些上限，並驗證直接載入遠方、依序生成和淘汰快取後重查，結果一致。若從起點補算超過預算，在本階段調整章節索引或快取策略，重跑同一組驗收。

### 生成版本與亂數域

`generation_version` 管理檢查點相容性。第 2 階段重排世界時升版，後續階段若改變已可存檔世界的地形、碰撞、生成物身分或其他存檔引用，也須升版。舊檢查點依現行規則拒絕載入。

亂數種子由各域的內容版本和穩定候選身分決定。第一次大改整體重抽，後續只更新需要重抽的域。單獨改樹種配方可以影響森林和檢查點相容性，場址與遭遇的抽選仍沿用原來的種子。這套規則取代 `seed_for` 現在把 16–20 對應回 15 的做法與各處寫死的版本覆寫。

### 生態區與環境場

環境場提供世界座標 `(x, z)` 的濕度、土質權重與擾動。生態區資源定義適生條件、各土質對應的地表材質與植被配方。區域以二維世界座標定位，讓同一里程的公路兩側能有不同生態。區域抽選遵守 landform 相容性，有多種候選時避免連續重複，只有一種時允許重複。交界兩側共用同一組生態區混合權重；近景、遠景與試玩場地圖皆從同一位置取樣。

### 樹種與林分

樹種是參數化生成器（TreeSpecies），每種生成多個變體並快取。枯死、將死、焦黑、斷頂、半埋由同一樹種推導，所以「死松」和「死闊葉樹」長相不同。MultiMesh 開逐棵顏色，加輕微傾斜與不等比縮放。樹幹碰撞照樹種的實際粗細。

林分以世界座標種子生成。母樹與子樹各依自己的樹根座標歸入唯一的 band。收集所有能延伸到該 band 的林分候選樹，依林分座標與候選樹編號固定排序、分配索引後，才套用本次遊玩的倒樹紀錄。每棵樹的規劃資料提供樹幹的位置、方向與粗細，供碰撞、鄰區導航與怪物避讓共用。

### 倒樹與檢查點

執行時沿用 `TreeImpact.forest_id(band, index)`。倒樹紀錄獨立於可淘汰的森林快取，區塊重建時跳過已倒的樹。[Checkpoint](../../rv/checkpoint.gd) 在 F6 寫入損壞紀錄時略過森林樹木的 `forest:` 項目，灌木和路旁設施沿用現行保存規則。

F9 在開始重建區塊前，從已驗證的快照取得玩家與所有車輛的碰撞範圍，和依種子規劃的樹幹比對。檢查涵蓋相鄰 band 和初次載入範圍外的車位。重疊的樹先記入本次倒樹紀錄，森林實體和導航烘焙都讀這份結果，再讓讀回的玩家與車輛開始模擬。空出的樹位恢復立木。

## 階段

| 階段 | 內容 | 完成條件 |

### 階段 2 驗收

- 兩個固定種子的彎道與升降節奏量得出差別。章節接縫連續，坡度、彎道半徑、側向範圍和道路自交檢查通過。
- 深谷橋、箱涵路堤和下切路段都能雙向開車、步行，怪物導航也能通過。若有涉水下切，另驗淺灘可通行且較深河床仍阻擋導航。測一個引道長度不足的候選，確認捨棄或調整後主路仍然連續。橋的出現符合章節規則。
- 測一組跨章節的場址衝突。正反順序查詢都保留同一個合法場址，其他場址的身分與內容抽選一致。正式教學能開車離開避難所。
- 依序生成、直接查遠方再回查前一章、淘汰快取後重查，三種順序得到相同規劃。舊生成版本的檢查點會被拒絕，當前版本的遠距冷啟動 F9 符合階段 0 的時間、單幀停頓與記憶體上限。

### 階段 5 架構驗收

- 固定種子在同一類地形產生兩種森林。駕車跨過沙地枯木林交界時，近景與遠景交替載入仍呈現相符的地表色調。
- 選一組跨 band 的母樹與子樹，以正反順序載入。撞倒其中一棵後開遠再折返，只有該樹消失；實體碰撞與接縫兩側導航都可通行。
- 分別撞倒兩棵樹，把房車停在其中一個樹位，另撞倒一株灌木或路牌，再執行 F6／F9。空出的樹位恢復立木，車位可安全駛離，灌木或路牌保留破壞狀態。另驗玩家站在樹位時可安全移動，以及停在初次載入範圍外的第二台車在折返後仍可駛離。
- 用階段 0 的基準，在同一台機器、畫質、種子、路線與車速下複測 P95 幀時間、最慢串流切片時間和 draw calls。
- 通過效能門檻並完成駕駛試玩後，定案樹木身分、跨 band 歸屬與共用樹幹幾何。分層責任與生態區介面等垂直切片驗收後才固定。

### 垂直切片驗收（階段 7 結束）

在一段正式公路上，從活的森林開進沙地枯木林，穿過一處水岸，遇霧後再折返。檢查地表辨識度、沒有樹冠時的視野、枯木的風聲、起霧後的巨人遭遇，以及交界兩側的玩法是否能只靠生態區旗標表達。通過後才固定生態區與各層之間的介面，再開始階段 8。

## 沙地枯木林（第一個新生態區）

- 地表：淡黃灰色的沙，有風紋，夾少量礫石。
- 地被：稀疏的乾草叢、沙堆、半埋的倒木，沒有一般的草。
- 樹：大多是枯木（白化的松、裂開的闊葉樹骨架、斷頂、半埋），零星幾叢活的矮灌木。
- 密度中低、群聚弱：遠方視野開闊，近處樹幹林立。
- 大氣與聲音：起風揚沙，霧偏乾霾；枯木吱嘎多，沒有葉響。

## 風險

- 地形、碰撞或存檔引用的變更會使舊檢查點失效。各階段依[生成版本與亂數域](#生成版本與亂數域)判斷是否升版，並驗證未改動的亂數域仍為相同候選抽出同樣內容。
- 樹種變體一多，每個 48 m 格子的 MultiMesh 數會暴增。每個生態區要限制同時使用的變體數；遠景可能要 impostor。
- 宣傳片鏡頭（`tests/playgrounds/promo/shots/`）與 `scripts/promo_scout.gd` 依賴現在的地形與樹位置，階段 2 之後要重新取景。
- 樣條路線的最近點查詢不再有解析導數，要確認效能與急彎處的穩定性。
