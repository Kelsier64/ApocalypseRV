# 風與沙塵

**進度。** 階段 1（`WorldWind`、乾燥度與沙塵量、終端機與天氣試玩場的讀值）已實作，契約見[環境](../systems/environment.md#風由天氣段推得)。階段 2（沙霧、飛沙與沙團、體積霧顏色、雨幕傾斜）已實作，等天氣試玩場驗收，契約見[環境](../systems/environment.md#沙塵的取樣與成本)。階段 3（風的底層、樹梢呼嘯、RV 嘯聲與拍打、強風遮蔽）已實作，等環境音試聽場驗收，契約見[環境](../systems/environment.md#風聲)；底層錄音試聽後選定微風用 A 組、強風與暴風用 B 組；樹梢呼嘯原本切得太暗、音質差，改用 bruno.auzet 的 gusts in a tree 並保留高頻葉聲，等試聽確認（2026-11-24）。階段 4 尚未開始。

## 目標

- 風成為天氣的一部分：分平靜到暴風四級，跟著天氣段變化，有方向也有陣風。
- 沙塵不另外抽選，而是由風力、乾燥與所在地貌算出。程序生成的地貌直接決定哪裡危險：開闊乾燥的地方強風時揚沙，暴風時變成沙塵暴；森林與濕地裡幾乎沒有。從林子開進草原，可能一頭撞進一片沙牆。
- 風與沙塵是威脅，不只是布景：沙塵縮短視野，強風蓋過遠處的怪物線索，側風推著 RV 走。
- 無風就是寂靜，延續環境音「寂靜為主」的方向。

## 已確認的設計決定

| 題目 | 決定 |
|---|---|
| 沙塵的來源 | 由風力、有沒有下雨與所在地貌算出，不是獨立的天氣。開闊乾燥地強風時揚沙，暴風時成為黃褐色的沙塵暴，視野縮得像大霧；森林與濕地裡幾乎沒有（2026-11-22）。 |
| 玩法影響 | 沙塵像霧一樣縮短視野。強風時遠處的車外聲（怪物腳步、叫聲）變小、方向變模糊，做法和引擎遮蔽相同，Slender Speaker 的旋律仍辨得出方向。另外有側風物理：側風推 RV，陣風讓方向盤抖，開闊地暴風時開車變難。怪物的感知與玩家狀態不變（2026-11-22）。 |
| 風聲 | 無風時完全沒有風聲。有風時才出現低頻為主、隨陣風起伏的風聲，刻意壓低高頻；強風再加上定位的樹梢呼嘯、RV 車殼嘯聲與鬆動零件拍打。在車廂內和其他車外聲一樣變悶，進入 POI 後停止（2026-11-22）。 |
| Slender Speaker | 只看霧，沙塵不算（2026-11-22）。 |
| 風與霧 | 風依這段的霧量抽：霧在靜風裡形成，中霧與濃霧最多微風，強風與暴風集中在無霧與薄霧時，濃霧和沙塵暴不會同時出現。霧的抽法與頻率不變。地面霧塊順風飄、強風時被撕薄；距離霧不隨風變（2026-11-23）。 |

以下是我代為決定、你可以否決的項目：

- **不擴充存檔。** 風不存進檢查點，由天氣段推得：`WorldWeather` 的亂數只在換段時抽取，段內狀態不變且已經存檔，所以把它和世界種子雜湊就能得到這一段的風力與基準風向。讀檔後同一段天氣有同樣的風。風不從 `WorldWeather` 的亂數抽取，既有種子的雨霧順序不變。用終端機強制設定的風在讀檔後回到自然值（符合 [CLAUDE.md](../../CLAUDE.md) 第 3 條）。
- **四級風力**：平靜、微風、強風、暴風。機率依霧量分列，見[環境](../systems/environment.md#風)；大雨時往上一級的機率提高，成為暴風雨。數值寫成常數，試玩後再調。新局的第一段固定平靜，出庫第一眼不會是沙塵暴。
- **風向與陣風**：每段一個基準風向，段內隨時間緩慢偏轉，最多約 30°。陣風是遊戲時間的平滑雜訊，種子從世界種子衍生，不讀寫任何亂數產生器，所以讀檔後的陣風也一樣。畫面、聲音與物理讀同一個陣風值，三者不會對不上。
- **乾燥度**：用 [terrain_landforms.gd](../../world/terrain/terrain_landforms.gd) 既有的 `MOISTURE` 與 `TREE_DENSITY` 依地貌過渡混合，濕度與樹越多越不起沙。峽谷、山脊、懸崖最乾，草原居中，濕地與森林盆地最少。下雨時沒有沙塵；第一輪不做雨後地面殘濕。
- **沙塵是全畫面效果**：在攝影機的位置取樣，和霧一樣套在整個戶外畫面。地貌交界的過渡區有幾百公尺，沙塵在其中漸變。
- **沙塵和霧的疊加**：取兩者中較近的遮蔽距離，不相乘；顏色依兩者的比重混合，偏土褐。沙塵只能把霧拉近，不能讓常駐遠景霧的終點變遠。天空地平線和霧用同一個顏色。
- **側風只算橫向**：只加橫向推力和它造成的側傾與偏擺力矩，不加一般的空氣阻力。現在的車沒有空氣阻力，加了會改變極速與油耗的平衡。推力隨風速平方增加，再乘上 RV 所在位置的受風係數，樹多或峽谷內較小。保證：平地上靜止或直線行駛的完好 RV，最強陣風也吹不翻；要高速過彎再加上暴風才可能翻車。
- **方向盤抖動**只是駕駛視角的視覺回饋，依側風推力的變化量決定，不改變操控輸入。
- **強風遮蔽和引擎遮蔽取較大者**，不相加，上限和引擎遮蔽同一級。
- **植被擺動不在第一輪。** 目前沒有任何擺動著色器，所有樹與草的材質都要改，另外開項目。雨幕隨風傾斜在第一輪。
- 沙塵粒子不進有屋頂的地方，沿用 `RainCover`；車頂完整的車廂內沒有沙塵。
- 過渡中讀檔時，風直接停在新一段的風力與風向，不從上一段過渡（檢查點沒有上一段的亂數狀態；2026-11-22 確認）。
- 每個階段實作前，先確認走 worktree 與 PR 或直接上 main。

## 設計

### 1. 風的狀態

- 新增 `WorldWind`（RefCounted），和 `WorldWeather` 一樣由 `WorldClock` 擁有，只讀天氣的段落與遊戲時間，不寫天氣。
- 對外提供：目前風力（含過渡）、風向、陣風、某個位置的風速，以及某組地貌條件下的沙塵量。地貌的乾燥度與受風係數是純函式，測試不必建世界。
- 換段時風力和雨霧一樣用 `TRANSITION` 平滑過渡。教學出庫前天氣停住時，風也停在平靜。
- 讀天氣的地方都要跟上：[terminal_commands.gd](../../equipment/terminal_commands.gd) 的 `weather` 輸出加上風的一行，另有 `wind` 指令強制風力；風的描述是 `WorldWind.description()`，`WorldWeather` 不知道風（還原後它沒有世界種子）；[天氣試玩場](../../tests/playgrounds/weather_playground.tscn) 的控制。
- [world_generator.gd](../../world/world_generator.gd) 的 Slender Speaker 判斷只讀天氣的霧量；沙塵不寫進霧量，這條規則不用改。

### 2. 畫面

- `WorldClock` 仍是戶外 `Environment` 的唯一寫入者（見[環境](../systems/environment.md#時鐘是戶外光照的唯一寫入者)）。沙塵經 `WorldAtmosphereProfile` 進來：設定檔新增沙塵的遮蔽距離、密度與顏色，`apply_time` 和霧一起合成。
- 體積霧的顏色跟著偏土褐，車燈與門燈照進沙塵時看得出光束。
- 沙塵粒子照 `WeatherRain` 的做法：跟著攝影機的固定種子 `MultiMesh`，位置由著色器依時間、風向與陣風計算，粒子數是固定的常數，每幀只更新參數。
- 雨幕依風向與風速傾斜，大雨加暴風時斜得最明顯。

### 3. 聲音

- **風的底層**：平靜時沒有聲音。微風、強風、暴風各一段立體聲迴圈，依風力交叉淡化，音量隨陣風起伏。素材先低通再進遊戲，避免重蹈錄音底噪「高頻太多、太突兀」的問題。走環境音的 `Outdoors` bus，在車廂內與屋頂下變悶，引擎轉速高時被壓低，進 POI 後停止。
- **定位聲**：森林裡強風時，由樹梢呼嘯在附近的隨機方位起落，森林權重沿用 `WorldAmbience` 的取樣。RV 在強風時有車殼嘯聲與鬆動零件拍打，用 `SoundLoop` 掛在車上；車板缺失越多，嘯聲越明顯。
- **強風遮蔽**：`Sfx` 新增風的遮蔽值，`Exterior` 的壓低取引擎遮蔽與風遮蔽的較大者，`Loudspeaker` 照引擎遮蔽的比例補回。
- RV 行駛時既有的車速風聲（[vehicle_audio.gd](../../rv/vehicle_audio.gd) `wind_level`）保留，和天氣的風分開。
- 素材來源、授權與規格照[音效系統重做](audio-overhaul.md#6-製作流程)。

### 4. 側風

- 新增 RV 的風力輔助（例如 `rv/wind_load.gd`），在車體的物理步中取 `WorldWind` 的風速與 RV 位置的受風係數，算出橫向推力，施加在車身側面的受風中心。受風中心高於重心，所以會側傾；前後不對稱，所以會偏擺。
- 側面積、係數與受風中心高度放在 [handling_profile.tres](../../rv/handling_profile.tres)，不寫死在程式裡，也不要讓 `chassis.gd` 繼續變大。
- 翻車判定沿用既有規則（見 [RV 擬真操控](rv-handling-rollover.md)）。

### 5. 測試

- 風：同一組種子與天氣亂數狀態得到同樣的風；存讀天氣後風相同；推算風不改變天氣亂數的狀態，[atmosphere_contracts.gd](../../tests/support/atmosphere_contracts.gd) 的雨霧順序照常通過；新局第一段平靜。
- 沙塵：同樣風力下，濕地與森林盆地的沙塵少於峽谷與山脊；下雨時為零；平靜時為零。
- 畫面：沙塵只把霧拉近，不推遠終點；地平線和霧同色；沙塵不改變天氣的霧量。
- 聲音：平靜時沒有風聲；強風遮蔽和引擎遮蔽取較大者而不相加；喇叭照比例補回；進 POI 後風聲停止。
- 側風：平靜時沒有推力；推力隨風速增加；平地上靜止的 RV 在最強陣風下不翻。數值從設定檔讀取，不寫死在測試裡。
- 風、沙塵、聲音與推力都不讀寫玩法或世界生成的亂數。

### 6. 試玩場

- [天氣試玩場](../../tests/playgrounds/weather_playground.tscn) 的 Playground 頁加上風力、風向與地貌（乾燥度）的控制，看沙塵、沙霧與雨幕傾斜。
- 風聲在[環境音試聽場](../../tests/playgrounds/ambience_playground.tscn)聽空地、樹林、車廂內與屋頂下的差別。
- 側風在可駕駛的試玩場加風力控制，比較直線、過彎與停車時的手感。

## 之後再做

- 樹、草與布料隨風擺動，輕物件被吹動。
- 沙塵從缺失的車板吹進車廂。
- 玩家步行時受風影響。
- 雨後地面殘濕，暫時不起沙。

## 風險

| 風險 | 對策 |
|---|---|
| 沙塵加上霧和夜晚，畫面暗到完全不能玩 | 疊加取較近者而不相乘；試玩場同時測大霧、夜晚與沙塵暴 |
| 側風讓翻車太常發生 | 「平地上靜止的 RV 不會被吹翻」寫成測試；推力有上限 |
| 風聲又變成刺耳的底噪 | 先低通並對齊響度，每批做兩三個版本給你挑 |
| 沙塵粒子的效能 | 照雨的做法用固定數量與固定的射線預算 |
