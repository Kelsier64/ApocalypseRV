# 音效系統重做

**進度。** 混音基礎、車門與車外預警已實作。原地拉轉的柴油錄音聽感仍不理想，行車時只剩引擎聲；正在把引擎改為顆粒合成，並補上路噪、風聲與換檔過程。

## 目標

- 每個聲音聽起來像實體：金屬是金屬，引擎是引擎，不再像 UI 嗶聲。
- 聲音是資訊：玩家能靠聲音判斷方向、距離、在車內或車外，以及怪物在做什麼。這是 [恐怖氛圍研究](../reference/research/lethal-company-horror-atmosphere.md#p1建立聲音資訊層) P1 的內容。
- 同一事件每次聽起來略有不同，但不消耗玩法用的亂數，固定種子重現的局不受影響。
- 新增一個聲音只需要做素材並寫一個資源檔，不必再寫合成程式。
- 混音分層，可以在設定裡分開調音樂、音效和環境音。

## 已確認的設計決定

| 題目 | 決定 |
|---|---|
| 是否重做 | 重做；先寫完整計畫（2026-11-18） |
| 素材來源 | 允許原創及 CC0 錄音。逐個來源記錄作者、授權連結和處理方式。路噪、風聲等行車層優先用 CC0 錄音，找不到合適的才用腳本離線生成。 |
| 首輪試聽 | 比較車門開鎖與關門、引擎怠速和拉轉、車外預警在車內外的差異。 |
| 設定滑桿 | 主音量、音樂、音效、環境音。世界內的聲音線索由音效滑桿控制。 |
| 引擎做法 | 顆粒合成：從柴油錄音離線剪出單次爆發的顆粒，執行時依轉速逐顆排列播放。這是「執行時不再合成」的唯一例外，素材本身仍是錄音。 |
| 引擎轉速 | `Chassis` 的轉速範圍與駕駛手感不變，只在聲音端把轉速對應到柴油的爆發頻率。 |
| 駕駛視角混音 | 引擎為主，路噪與風聲隨車速增加；高速時兩者接近，車外預警仍要辨得出方向。 |
| 換檔 | 只在聲音端加約 0.3 秒的換檔過程：負載鬆開、轉速滑到新檔位、再加回負載，配一聲排檔機械聲。動力不中斷。 |
| 車內外遮蔽 | 依聲源位置動態分配：聲源在車廂內走 `Cabin`，否則走 `Exterior`。聽者在車廂內時悶 `Exterior`，在車外時悶 `Cabin`。 |
| POI 內聽外面 | 暫時維持靜音。室內是否聽得到 RV 遭攻擊屬於遭遇設計，階段 4 與怪物特徵聲一起討論。 |

以下是我代為決定、你可以否決的項目：

- **素材改為離線製作的音檔**，除引擎顆粒外執行時不再合成。程序變化來自變體抽選、音高與音量抖動、依強度選層，以及依世界種子擺放的環境聲源。
- 素材規格：44.1 kHz、16 bit。3D 音源一律單聲道；環境底噪與音樂可用立體聲。短音用 WAV，超過 10 秒的迴圈用 Ogg Vorbis。
- 優先為腳步、撞擊等高頻事件準備多個變體。首輪車門各用一段錄音，配合小幅音高變化。
- 由音效服務持有專用亂數，直接抽取音檔與音高、音量變化。`AudioStreamRandomizer` 在 Godot 4.7.2 會消耗全域亂數，遊戲中仍有怪物行為使用同一來源。遠距發悶沿用 `AudioStreamPlayer3D` 的距離濾波。
- 遷移順序：先做基礎與 RV 試點，你聽過並同意方向後才推廣到其他模組。
- 引擎聲源不在車廂範圍內，但駕駛聽到的引擎是透過車廂傳進來的，因此引擎固定走 `Cabin`，不套用位置規則。

## 設計

### 1. Bus 配置

[default_bus_layout.tres](../../default_bus_layout.tres) 固定以下結構：

```
Master
├─ Music           背景配樂
├─ UI              畫面操作回饋，跟隨音效滑桿
└─ World           受傷與一般致死的悶聲濾波
   ├─ Effects      音效滑桿
   │  ├─ Exterior  車外聲源；聽者在車廂內時變悶
   │  ├─ Cabin     車廂內聲源與引擎；聽者在車外時變悶
   │  └─ Voice     收音機人聲，保留既有空間距離
   └─ Ambience     環境音滑桿
      └─ Rain      只對下雨套用原有遮蔽濾波
```

- 受傷悶聲掛在 World，UI 與音樂不受影響。
- 雨聲的固定 `Rain` bus 送往 `Ambience`，雨遮只濾掉雨聲。
- 一般致死在 `World` 變悶，斷頭致死沿用 `GameSettings` 暫時靜音 `Master` 的機制。見 [GDD](../../GDD.md)。
- `Music` 與 `UI` 目前還沒有聲源，對應滑桿要到階段 5 有配樂與操作聲後才有作用。
- 耳鳴與甦醒吸氣是玩家自身的聲音，目前在 `Effects` 下，會被受傷悶聲一起濾掉。階段 3 遷移時移到不受 World 悶聲影響的位置。

### 2. 音效事件層

`core/audio/` 目前有：

- **`SoundEvent`（Resource）**：音檔候選、音量、音高變化、bus 與衰減距離。
- **`Sfx`（autoload）**：`play(event, source, local_position)` 播放並跟隨一次性 3D 音效。池掛在目前聆聽的 viewport，POI 出入口會切換。首輪上限為 12，滿時略過下一個一次性音效。
- **亂數**：`Sfx` 使用自己的亂數產生器，絕不讀寫玩法或世界生成的亂數。
- **事件檔位置**：`assets/audio/events/<domain>/<name>.tres`，例如 `rv/door_open.tres`。素材放在同一個 domain 的 `assets/audio/<domain>/`。

階段 3 遷移時再加入：

- **`SoundAttenuation`（Resource）**：距離衰減預設，至少分成 `near`（手邊操作，約 15 m）、`vehicle`（RV 與設備，約 50 m）、`loud`（槍聲、爆炸，約 80 m）、`landmark`（Slender Speaker）。
- **`SoundLoop`（Node3D 元件）**：持續聲源（輪胎滑移、刮地、絞碎機、雨），由擁有者每幀餵入參數。引擎因為是顆粒合成，不走這個元件。
- `SoundEvent` 的強度曲線、冷卻時間、優先度與事件各自的發聲限制，以及池滿時依優先度搶占。
- `Chassis.feedback(kind, ...)` 這類字串介面改成直接傳 `SoundEvent`。排檔、手煞車、坡板、維修蓋、千斤頂、安裝完成、受阻各自獨立。

### 3. 引擎與車輛

- **顆粒引擎**：從同一輛柴油車的怠速與拉轉錄音中，依爆發脈衝切出單次爆發的顆粒，按原轉速建表。執行時依目前轉速選最接近原轉速的顆粒，以爆發間隔逐顆排列並交疊淡化，再依負載在加油與收油兩組顆粒之間混合。各缸輪流使用不同顆粒，保留柴油的不均勻感。
- 轉速對應：`Chassis` 的怠速到上限對應到錄音裡怠速到最高拉轉的爆發頻率。
- 換檔過程與駕駛視角混音見上方決定表。
- 啟動、熄火各自是一次性錄音；啟動失敗之後再加。
- **路噪與風聲**：路噪依 [tire_model.gd](../../rv/tire_model.gd) `surface_grip` 背後的 `WorldField.road_query` 分柏油、路肩、越野三種，音量與亮度隨車速提高；風聲在中高速後才明顯。
- 撞擊依強度選輕、中、重三層，重撞再疊一層玻璃或車殼撕裂聲。
- 車殼受怪物攻擊、面板毀壞、碎片落地沿用 [panel_damage_effect.gd](../../rv/panel_damage_effect.gd) 的時序，只換素材並改走事件層。

### 4. 空間與遮蔽

- **車內外**：用聆聽者在車身局部空間的位置判定，在車頂時歸為室外。聽者在車廂內時，以約 0.3 秒過渡降低 `Exterior` 的音量與高頻；在車外時同樣處理 `Cabin`。門片角度和缺失車板都會減少遮蔽。
- **聲源分配**：一次性音效與持續聲源都用同一個函式，依聲源位置決定走 `Cabin` 或 `Exterior`。`Voice`、`UI` 等事件指定的 bus 不受這條規則影響。
- **引擎遮蔽**：引擎轉速高時 `Exterior` 再小幅降低，讓「開車時聽不清外面」成為代價（研究 P1-2）。
- **POI 室內**：進入 POI 室內時，World 加上依室內大小設定的殘響。小房間、走廊、大廳三種預設，由 POI 設定資料提供。進入 POI 後只聽得到室內世界。
- 非空間化的環境底噪保持很小聲，避免掩蓋方向判斷（研究 P1-4）。

### 5. 新增的聲音層

- **玩家腳步**：依路面（柏油、路肩、泥土、草地）、RV 車廂地板、車頂金屬、室內地板分別取變體。跑步更大聲，蹲下更小聲。玩家自己的腳步依位置走 `Cabin` 或 `Exterior`。
- **怪物特徵聲**：每種怪物有可以學習的移動聲與預兆聲（研究 P1-3）。具體規則要逐隻討論，見上方「待你決定」。
- **環境**：日、夜、霧、森林、公路各一層底噪，依時間與天氣交叉淡化。另外依世界種子在區塊內擺放少量空間化環境聲源，例如風吹樹梢、遠處金屬吱嘎、夜間蟲鳴，隨區塊串流載入與卸載。
- **操作**：撿起、放下、背包、製作台、平板各自有聲音。畫面操作聲走 UI bus。

### 6. 製作流程

- 有 REAPER 專案或可重製的剪輯腳本時，放入 `art_source/audio/<domain>/`。試點流程和來源見 [RV 錄音](../../assets/audio/rv/README.md)。
- 音量規格：一次性音效峰值 -1 dBFS；迴圈與環境底噪用響度對齊，同類事件之間的差距在 ±2 dB 內，最終以試玩為準。
- 每個素材資料夾的 README 記錄來源、授權和製作方式。
- 每批素材先檢查峰值、頻譜和迴圈接縫，再在試玩場景驗收辨位和聽感。

### 7. 測試

- 驗證所有 `assets/audio/events/` 下的事件：串流存在、引用的 bus 存在、數值範圍合理。數值從資源讀取，不寫死在測試裡。
- 驗證 `Sfx` 池的上限、安全切換到 POI 的 `World3D`，以及 POI 播放時拒絕公路世界的來源。加入優先度後再驗證搶占。
- 車內外切換時，`Exterior` bus 在車內的截止頻率與音量低於車外（只比較相對關係）。
- 顆粒引擎：轉速越高單位時間的爆發越多、輸出不爆音、播放不改變全域亂數。
- 播放聲音不改變世界生成或遭遇用的亂數狀態。
- 現有測試繼續通過：[test_body_recovery.gd](../../tests/test_body_recovery.gd) 的主音量靜音、[test_slender_speaker_acquisition.gd](../../tests/test_slender_speaker_acquisition.gd) 的迴圈、[test_item_player.gd](../../tests/test_item_player.gd) 的收音機換台。

### 8. 試玩場景

用 [RV 音效試點](../../tests/playgrounds/rv_audio_playground.tscn) 比較車內外、開關門、怠速到拉轉及同一個車外預警聲。試聽時先試著指出警示聲的方向，再比較關門和開門，最後確認引擎拉轉時仍可辨認預警。行車聲在可駕駛的試玩場景驗收。試點驗收後移除 A/B 切換和被取代的合成聲。POI 殘響測試追加在後續階段。

## 風險

| 風險 | 對策 |
|---|---|
| 素材量大，製作時間主要花在聲音本身 | 階段 2 只做 RV；之後依遭遇與操作頻率排序 |
| 我無法親耳判斷好壞 | 每批先做客觀分析，再交給你試聽；必要時一次做兩三個版本讓你挑 |
| `AudioStreamPlayer3D` 太多造成效能負擔 | 全域聲源池與上限；試玩時量測 |
| 顆粒引擎在腳本裡逐樣本混音，可能吃幀時間或斷音 | 緩衝只排約 0.1 秒，試玩場景顯示斷音次數；必要時改成原生擴充 |
| 拉轉錄音是原地空轉，沒有真正帶負載的音色 | 負載感先靠顆粒選擇與音量；找到帶負載的同車錄音再補 |
| 車頂、破口或 POI 切換讓遮蔽與定位出錯 | 測試車頂判定、門片角度、車板破損和不同 `World3D` 的聆聽切換 |
| 遷移期間新舊兩套系統並存 | 每個階段結束時刪掉該階段取代的舊程式，不留相容分支 |
