# 音效系統重做

**進度。** 階段 1–4 完成並已試聽。階段 5 的怪物聲音與玩家腳步完成並已在試聽場驗收；接著做環境音、操作聲與配樂。

## 目標

- 每個聲音聽起來像實體：金屬是金屬，引擎是引擎，不再像 UI 嗶聲。
- 聲音是資訊：玩家能靠聲音判斷方向、距離、在車內或車外，以及怪物在做什麼。這是 [恐怖氛圍研究](../reference/research/lethal-company-horror-atmosphere.md#p1建立聲音資訊層) P1 的內容。
- 同一事件每次聽起來略有不同，但不消耗玩法用的亂數，固定種子重現的局不受影響。
- 新增一個聲音只需要做素材並寫一個資源檔，不必再寫合成程式。
- 混音分層，可以在設定裡分開調音樂、音效和環境音。

以下是我代為決定、你可以否決的項目：

- **素材改為離線製作的音檔**，執行時播放並混合素材。程序變化來自變體抽選、音高與音量抖動、依強度選層，以及依世界種子擺放的環境聲源。
- 素材規格：44.1 kHz、16 bit。3D 音源一律單聲道；環境底噪與音樂可用立體聲。短音用 WAV，超過 10 秒的迴圈用 Ogg Vorbis。
- 優先為腳步、撞擊等高頻事件準備多個變體。首輪車門各用一段錄音，配合小幅音高變化。
- 由音效服務持有專用亂數，直接抽取音檔與音高、音量變化。`AudioStreamRandomizer` 在 Godot 4.7.2 會消耗全域亂數，遊戲中仍有怪物行為使用同一來源。遠距發悶沿用 `AudioStreamPlayer3D` 的距離濾波。
- 遷移順序：先做基礎與 RV 試點，你聽過並同意方向後才推廣到其他模組。
- 引擎艙在車廂外，引擎依位置規則走 `Exterior`，駕駛聽到的是隔著車殼的悶聲；引擎播放器多給一點音量補回來。路噪與風聲是車內錄音，固定走 `Cabin`。車門聲兩側一樣，固定走 `Effects`。
- 車板受擊與毀壞是車殼本身的聲音，和車門一樣固定走 `Effects`；碎片落地依位置分配。
- 耳鳴走新的 `Self` bus：直接送往 `Master`，不受受傷悶聲影響，音量跟隨音效滑桿，斷頭致死時一起靜音。
- 耳鳴用一段 CC0 的穩定 3.1 kHz 錄音做迴圈，比原本合成的 1.9 kHz 高。
- 油桶的爆炸與落地聲維持原本預先烘焙的 22,050 Hz 檔案，留在 `assets/effects/barrel_blast/`，只改走事件層。
- 戶外回音的大小依聽者距離調整：靠近時是事件設定的回音量，到事件最遠可聽距離時多 9 dB，和 Slender Speaker 一樣越遠越濕。
- 引擎遮蔽在車廂內或距引擎艙 4 m 內最強，20 m 外消失。引擎改走自己的 `Engine` bus，遮蔽不會壓到引擎本身。
- 室內預設：地堡用小房間，兩種樓梯間用走廊，無燈柱廳與巨型避難所用大廳。

## 設計

### 1. Bus 配置

[default_bus_layout.tres](../../default_bus_layout.tres) 固定以下結構：

```
Master
├─ Music           背景配樂
├─ UI              畫面操作回饋，跟隨音效滑桿
└─ World           受傷與一般致死的悶聲濾波
   ├─ Effects      音效滑桿
   │  ├─ Exterior  車外聲源；聽者在車廂內時變悶
   │  │  ├─ Loudspeaker  Slender Speaker 直達聲，硬限幅
   │  │  └─ OutdoorEcho  純濕聲戶外殘響，聲源自行決定送出量
   │  ├─ Cabin     車廂內聲源、路噪與風聲；聽者在車外時變悶
   │  ├─ Engine    直六引擎與啟動、熄火；和 Exterior 一樣隔著車殼，不受引擎遮蔽
   │  └─ Voice     收音機人聲，保留既有空間距離
   └─ Ambience     環境音滑桿
      └─ Rain      只對下雨套用原有遮蔽濾波
Self               玩家耳鳴，跟隨音效滑桿，不受 World 悶聲影響
```

- 受傷悶聲掛在 World，UI 與音樂不受影響。
- 聽者在 POI 室內時，該室內的殘響預設插在 `Effects` 第一格，回到戶外時移除。
- 雨聲的固定 `Rain` bus 送往 `Ambience`，雨遮只濾掉雨聲。
- 一般致死在 `World` 變悶，斷頭致死沿用 `GameSettings` 暫時靜音 `Master` 的機制。見 [GDD](../../GDD.md)。
- `Music` 與 `UI` 目前還沒有聲源，對應滑桿要到階段 5 有配樂與操作聲後才有作用。

### 2. 音效事件層

`core/audio/` 目前有：

- **`SoundEvent`（Resource）**：音檔候選、音量、音高變化、bus、距離衰減預設、冷卻時間、優先度與戶外回音量。冷卻內重複播放同一事件會被略過，連續碰撞不會占滿聲源池；冷卻跨所有聲源共用，多隻怪物同時發出的事件不設冷卻。優先度：碎片 0，操作與撞擊 1，槍聲與爆炸 2。
- **`SoundAttenuation`（Resource）**：距離衰減預設，放在 `assets/audio/attenuation/`：`near`（手邊操作，約 18 m）、`vehicle`（RV 與設備，約 55 m）、`loud`（槍聲、爆炸，約 90 m）。Slender Speaker 的喇叭有自己的距離曲線與回音層（見[敵人系統](../systems/enemies.md#slender-speaker)）。
- **`SoundLoop`（AudioStreamPlayer3D）**：持續聲源，由擁有者每幀餵入音量與音高；從自己的亂數決定的隨機位置開始播放，音量趨近零時停止。RV 的路噪、風聲、輪胎滑移、刮地與絞碎機用它。引擎各層必須同步，使用獨立的同步串流。
- **`Sfx`（autoload）**：`play(event, source, local_position, gain_db)` 播放並跟隨一次性 3D 音效，`gain_db` 依強度調整單次音量。池掛在目前聆聽的 viewport，POI 出入口會切換。上限為 12；池滿時，新事件接手優先度較低的最舊聲道，沒有可接手的就略過。`stop_from(source)` 停掉仍跟隨某個聲源的音效，例如中斷的換彈。
- **非空間聲音**：雨與耳鳴是一般的 `AudioStreamPlayer`，直接播放預載的音檔。
- **亂數**：`Sfx` 使用自己的亂數產生器，絕不讀寫玩法或世界生成的亂數。
- **事件檔位置**：`assets/audio/events/<domain>/<name>.tres`，例如 `rv/door_open.tres`。素材放在同一個 domain 的 `assets/audio/<domain>/`。

- `Chassis.feedback(event, at)` 直接傳 `SoundEvent`，RV 的操作回饋各有錄音。換檔、啟動與熄火、碰撞會改變音訊狀態或依強度選層，留在 `VehicleAudio.play_cue`。
- `SoundEvent` 的強度曲線與事件各自的發聲限制還沒有聲音需要，等需要時再加。

### 3. 引擎與車輛

- **直六引擎**：轉速、油門與換檔的播放行為見 [RV 系統](../systems/rv.md)。
- 換檔過程與駕駛視角混音見上方決定表。
- 啟動、熄火各自是一次性錄音；啟動失敗之後再加。
- **路噪與風聲**：路噪依 [tire_model.gd](../../rv/tire_model.gd) `surface_grip` 背後的 `WorldField.road_query` 分柏油、路肩、越野三種，音量與亮度隨車速提高；風聲在中高速後才明顯。
- 撞擊依強度選輕、中、重三組錄音，組內較輕的撞擊最多小 6 dB；重撞錄音已含玻璃碎裂。
- 車殼受怪物攻擊、面板毀壞、碎片落地沿用 [panel_damage_effect.gd](../../rv/panel_damage_effect.gd) 的時序，只換素材並改走事件層。

### 4. 空間與遮蔽

- **戶外回音**：`SoundEvent.outdoor_echo_db` 高於 -80 時，`Sfx` 在 `OutdoorEcho` 加播一份濕聲。回音用自己最多四個聲源，不占一次性音效的 12 個；只在聲源走 `Exterior` 且聽者在戶外世界時播放。槍聲 -12 dB，爆炸 -10 dB。
- **車內外**：用聆聽者在車身局部空間的位置判定，在車頂時歸為室外。聽者在車廂內時，以約 0.3 秒過渡降低 `Exterior` 與 `Engine` 的音量與高頻；在車外時同樣處理 `Cabin`。門片角度和缺失車板都會減少遮蔽。
- **聲源分配**：`Sfx.bus_at` 依位置決定走 `Cabin` 或 `Exterior`；`SoundEvent.occlusion_by_position` 關閉時改用事件指定的 bus，`Voice`、`UI` 與車門都是這種。RV 自己的持續聲源用 `VehicleAudio.bus_for_local` 套同一條規則，引擎固定走 `Engine`。
- **引擎遮蔽**：`VehicleAudio.engine_masking` 隨轉速增加、隨聽者離引擎艙的距離減弱。`Sfx` 依它把 `Exterior` 最多壓低 `ENGINE_MASK_DB`，再把其中三分之二補回 `Loudspeaker`，讓「開車時聽不清外面」成為代價（研究 P1-2）但預警仍可定位。
- **POI 室內**：每個 `InteriorProfile` 的 `reverb` 指定 [assets/audio/rooms/](../../assets/audio/rooms/) 的小房間、走廊或大廳預設，`PoiInstanceManager` 切換聆聽視窗時一併交給 `Sfx`。進入 POI 後只聽得到室內世界，雨聲也停。
- 非空間化的環境底噪保持很小聲，避免掩蓋方向判斷（研究 P1-4）。底噪在階段 5 才有聲源。

### 5. 新增的聲音層

- **玩家腳步**：依路面（柏油、路肩、泥土、草地）、RV 車廂地板、車頂金屬、室內地板分別取變體。跑步更大聲，蹲下更小聲。玩家自己的腳步依位置走 `Cabin` 或 `Exterior`。規則與契約見[玩家](../systems/player.md#腳步聲)。
- **怪物特徵聲**：每種怪物有可以學習的移動聲與預兆聲（研究 P1-3）。規則見上方的決定，實作與契約見[敵人與遭遇](../systems/enemies.md#怪物聲音)。
- **環境**：日、夜、霧、森林、公路各一層底噪，依時間與天氣交叉淡化。另外依世界種子在區塊內擺放少量空間化環境聲源，例如風吹樹梢、遠處金屬吱嘎、夜間蟲鳴，隨區塊串流載入與卸載。
- **操作**：撿起、放下、背包、製作台、平板各自有聲音。畫面操作聲走 UI bus。

### 6. 製作流程

- 有 REAPER 專案或可重製的剪輯腳本時，放入 `art_source/audio/<domain>/`。試點流程和來源見 [RV 錄音](../../assets/audio/rv/README.md)。
- 音量規格：一次性音效峰值 -1 dBFS；迴圈與環境底噪用響度對齊，同類事件之間的差距在 ±2 dB 內，最終以試玩為準。
- 每個素材資料夾的 README 記錄來源、授權和製作方式。
- 每批素材先檢查峰值、頻譜和迴圈接縫，再在試玩場景驗收辨位和聽感。

### 7. 測試

- 驗證所有 `assets/audio/events/` 下的事件：串流存在、引用的 bus 存在、數值範圍合理。數值從資源讀取，不寫死在測試裡。
- 驗證 `Sfx` 池的上限、安全切換到 POI 的 `World3D`，以及 POI 播放時拒絕公路世界的來源。加入優先度後再驗證搶占。
- 車內外切換時，`Exterior` 與 `Engine` bus 在車內的截止頻率與音量低於車外（只比較相對關係）。
- 戶外回音只在戶外播放且有上限；引擎拉轉時遮蔽 `Exterior`、喇叭壓得較少、引擎不遮蔽自己；每種室內都有殘響預設，進出 POI 時插入與移除。
- 怪物聲音：各怪物安靜的狀態真的無聲，暴露的狀態才出聲；腳步表對上步態片段的著地點；攻擊預備聲優先度高於叫聲與腳步。
- 玩家腳步：每種地板分類正確（標記、RV 車廂與車頂、公路、路肩、地面）；步數跟著走過的距離，衝刺與蹲行改變步距與音量，落地多一步，站著不出聲。
- 直六引擎：驗證素材週期、轉速與油門跨層混音，以及點火與熄火的銜接。
- 播放聲音不改變世界生成或遭遇用的亂數狀態。
- 現有測試繼續通過：[test_body_recovery.gd](../../tests/test_body_recovery.gd) 的主音量靜音、[test_slender_speaker_acquisition.gd](../../tests/test_slender_speaker_acquisition.gd) 的迴圈、[test_item_player.gd](../../tests/test_item_player.gd) 的收音機換台。

### 8. 試玩場景

用 [RV 音效試點](../../tests/playgrounds/rv_audio_playground.tscn) 比較車內外、開關門、怠速到拉轉及同一個車外預警聲。同一場景可以逐一播放 `assets/audio/events/` 下的每個事件，聲源可放在車旁或車廂內，另有雨與耳鳴。殘響預設可以在同一場景切換試聽，實際室內在遊戲中驗收。怪物在實際行為中的聲音在 [怪物音效試聽場](../../tests/playgrounds/monster_audio_playground.tscn) 聽。玩家腳步在 [腳步試聽場](../../tests/playgrounds/footstep_playground.tscn) 逐一走過每種材質，實際地形的分類在遊戲中驗收。行車聲在可駕駛的試玩場景驗收。

## 風險

| 風險 | 對策 |
|---|---|
| 素材量大，製作時間主要花在聲音本身 | 階段 2 只做 RV；之後依遭遇與操作頻率排序 |
