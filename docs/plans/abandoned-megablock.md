# 廢棄巨型住宅副本：灰井住宅城

日期：2026-10-22，第二版。依使用者回饋改為簡單對稱外觀、每層一個大空間、隨機內容，取消中庭與固定樓層用途。狀態：設計提案與新版兩張概念圖完成；下列遊戲內容、尺寸、時間及數值均為製作目標，尚未實作或實機驗收。

## 1. 設計核心

**一棟簡單、對稱的巨大廢棄住宅樓。每層是一整片開放大空間，由柱列、廢家具與設備形成隨機配置；玩家停好 RV，上樓搜刮，再沿樓梯把有用物資搬回車。**

暫名「灰井住宅城」，遊戲顯示名 `GRAYWELL BLOCK`，提議定義 ID `graywell_megablock`，室內 profile `megablock`。它原是工業聚落的集中住宅，周邊只留下低矮廢墟、舊服務道路與重新長回的森林，可放進目前公路世界。

樓內保留集體居住、臨時避難與維護設備的痕跡。建築辨識點是完整長方體、規則窗格與置中的入口。恐怖感來自空曠樓面、重複柱列、家具遮蔽及深處的動靜。每層不預先指定住宅、食堂或機房用途，也不生成小房間迷宮。

建議首趟含額外搜刮的探索目標為 25–40 分鐘，熟悉操作後直接尋找主目標約 10–15 分鐘；需靠首版實際遊玩調整。

## 2. 建築外觀與尺度

![簡單對稱的完整量體](../art/graywell-megablock/exterior-concept-v2.png)

| 項目 | 建議製作規格 |
|---|---|
| 主量體 | 約 96 × 72 m，單一完整長方體，正面左右對稱，層層同寬；中央不挖空 |
| 高度 | 外觀約 24 層、層距 4.5 m，含屋頂收邊約 116 m；平直輪廓，灰盒時確認比例 |
| 每層空間 | 完整連續樓板、天花板與規則柱列，兩側設成對樓梯核心；不設中庭、連橋或內部分房 |
| 室外場址 | 先以約 144 × 144 m 預留建築、服務前庭、停車與接近動線；最終以真實占地及轉彎驗證定案 |
| 可玩首版 | L1–L4 四個大樓面；每層陳設與內容獨立抽取，上方樓層作可見封閉量體 |
| 完整內容擴充 | 增加 L5、L6，形成六層可玩區；使用相同隨機內容池，高層住宅與整棟屋頂另行排期 |
| RV 接近 | 前庭停靠區、旁側平坦搬運路；主入口台階之外設服務坡道 |

外觀只保留寬混凝土樓層帶、重複窗格、齊平柱線、成對樓梯核心與置中雨棚。減少外露管線、突出的機電塔、退台及屋頂零件。對稱要求用於建築量體與立面分格；污漬、雜草及散落物可以自然變化。上方以暗窗與封閉樓板表現未開放樓層，可玩區邊界須有實際碰撞與合理封口。

概念圖用來討論量體與氣氛，樓數、屋頂細節、樓梯、坡道和支撐均須依灰盒規格重作。圖中材質細節較正式低模版本豐富；實作沿用 D 風格的簡單幾何、粗材質與冷灰／土褐色。第一版中庭圖已退為歷史參考。

## 3. 單層大空間與隨機生成

![一個樓層就是一個完整大廳](../art/graywell-megablock/open-floor-concept-v2.png)

每層均是一個完整大廳。樓板網格可以拆件重複，以便製作及裁切，但不代表遊戲內房間。固定建築骨架提供可預期的結構，其餘配置依副本 seed 及樓層 ID 生成：

| 固定建築骨架 | 每次初訪隨機內容 |
|---|---|
| 外框、層高、承重柱列、連續樓板與天花板 | 床架、沙發、桌椅、貨架、箱子與設備的組合、數量、朝向及位置 |
| 置中地面入口、兩側完整連通的樓梯 | 空曠區與較密陳設群的分布，不按樓層綁定功能 |
| 樓梯落地平台及必要通行淨空 | 物資、主目標、敵人及可變照明配置 |

兩側樓梯直接連通可玩樓層；主物資從入口層以外、實際路徑距離足夠的合法位置抽取，不固定在 L3、最高層或某間維修庫。探索順序由玩家選擇，返程依當次位置使用較近樓梯。

```text
RV ↔ L1 大樓面 ↔ 兩側樓梯 ↔ L2／L3／L4 大樓面
       隨機陳設與物資           隨機陳設、主目標與遭遇
```

主目標先用既有標準引擎 Item，暫定 80% 耐久，作為有用的備用動力／回收設備；額外物資包含大容量電池、引擎維修包與一般補給。獎勵數量、電池電量和收益在內容階段調整，不新增道具類別或製造配方。

大型引擎沿用雙手持物規則，不能同時拿手電筒。因此樓梯保留低亮度固定照明，路線夠寬、避免跳躍與梯子，取得物資不封死玩家出口。本版使用兩側樓梯提供返回選擇，不安排固定栓門捷徑。

生成流程：先建立大樓面與柱列／樓梯 → 抽選稀疏陳設群 → 檢查碰撞與導航 → 放入物資及敵人。樓梯平台、入口與至少一條可搬運通道保留淨空；不合格陳設有界重抽，仍不合格就減少陳設。此通路由當次配置驗證，不固定一條預寫主路。主通行淨寬先以約 2.8 m、樓梯門洞 2.4 × 2.8 m、層距 4.5 m 起步，再以正式玩家、大型道具和 Raker 驗證。家具形成局部遮蔽，不能圍出封閉小房間或占滿整層。

## 4. 恐怖節奏與美術

1. **接近：** 公路轉角先露出低層立面，進入前庭抬頭才感受到整座住宅城。預設霧下仍須看清入口，不以修改全世界霧距來保證遠景。
2. **進場：** 門後是一整片深入暗處的柱列大廳，零散家具留下住戶生活痕跡；樓梯門的微光提供方向。
3. **深入：** 每層陳設重新組合，空曠區與家具群交替。Raker 可能從柱後或貨架側出現，追擊依正式 AI 的視線、距離與導航發生。
4. **取得：** 玩家在當次抽選的設備／物資群找到主目標，依已探索位置選擇搬運回程。
5. **撤回：** 雙手搬運、樓梯轉角與既有敵人位置形成壓力；不因拾取目標憑空生成背後追兵。

首版以全副本合計 2 隻 Raker 起步，樓層及位置從合法點隨機抽取，避開地面入口與樓梯落點的近距離伏擊；之後再試 2–4 隻的配置變化。完整樓板隔開垂直視線，大廳長視線與多層導航仍需實機檢查。油桶人留待擴充，只在退避空間足夠且不封死通路的隨機點配置。Slender Speaker 不放進這次室內副本。

照明以外牆窗光、柱列陰影、局部熄燈與樓梯暖燈分層。固定應急燈屬室內照明，不連接 RV 電網。室內使用獨立 Environment，不繼承戶外濃霧。必要實體標誌使用英文，如 `EXIT`、`STAIRS`、`L2`；不把玩法提示烘進牆面貼圖。

優先模組：立面窗格、外牆、大樓板、天花板、方柱、樑、樓梯平台與核心筒，以及可隨機組合的床架、沙發、桌椅、貨架、箱子與機電設備。建築骨架用原生幾何精確組裝；複雜靜態家具可用 ComfyUI 分件產生並檢查。Visuals 與 Collision／互動／物資標記保持分離，同款重複件共享資產。

## 5. 分階段製作計畫

目前只交付本設計與概念圖。實作建議依下列階段交付可檢查成果，再依回饋調整下一階段；本表不代表已開始開發。

| 階段 | 交付物與工作 | 完成條件 |
|---|---|---|
| 1：對稱量體與大樓面灰盒 | 獨立測試場：簡單對稱外殼、前庭、一個完整大樓面與成對樓梯，再複用至 L1–L4 | 每層均為一個大空間、無中庭；正式玩家及大型引擎可經樓梯回 RV，無卡門或強制跳躍 |
| 2：隨機樓層與住宅副本支援 | 新增 `megablock` profile／組裝分流、向上樓層、按樓層記錄的陳設 manifest、導航與內容快照；接入進出及地圖 | 不同 seed 的陳設與物資位置有差異，各層保持開放及可達；進出／取消／重返／室外讀檔保留配置，不重抽或複製；原地堡不受影響 |
| 3：簡化建築與室內美術 | 先完成一組重複立面格及含柱列／窗光的大樓面樣板，再延伸整棟、陳設群、燈光與生活痕跡 | 外觀對稱簡單，樓內有大空間尺度與清楚暗部；替換外觀保留碰撞及通路 |
| 4：完整一趟內容 | 主物資、隨機散落物、2 隻隨機放置 Raker、搜刮點、音效與雙手搬運；不綁樓層用途 | 多個 seed 可完成準備→探索→取得→搬運→回車；量測耗時、手電電量與收益，回訪不補貨 |
| 5：正式世界接入 | 新 POI 定義、低頻大型場址排程、平地及道路／河川避讓、跨區塊保護、串流與效能調整 | 實際輪驅停靠、卸載／重返、讀檔及夜間可見性正常；量測接近、載入、大樓面渲染、追擊及返回成本後才納入正式生成 |
| 6：六層與隨機內容擴充 | 新增 L5／L6、更多陳設群與稀疏／密集配置、照明變體及合格位置的選做油桶人 | 各 seed 保證目標及返程可達，每層仍為一個大空間，完成六層搬運、導航、保存與效能驗證；上方整棟探索另行設計 |

首版範圍包含四層開放空間、隨機內容與樓梯搬運。可運作電梯、整棟逐層串流、整座建築破壞、新 Boss、任意外牆攀爬及室內磁碟存檔留作後續獨立需求。

## 6. 技術落地與已知限制

以下依 2026-10-22 工作樹的 [POI 共用規範](../guides/poi-authoring.md)、[地堡契約](../guides/bunker-interior.md) 與 [架構](../../architecture.md) 核對，非新功能驗收結果。

| 範圍 | 目前能力與計畫接點 |
|---|---|
| 外部資產 | 使用 `INSTANCE_ENTRANCE`；外觀 `.tscn`＋`world/poi_definitions/` 新定義，包含真實 building／site bounds、Entrance、ReturnPoint。登錄集中於 [poi_config.gd](../../world/poi_config.gd) |
| 室內類型 | 目前只接受 `bunker`。[poi_instance_manager.gd](../../world/instances/poi_instance_manager.gd) 目前統一建立 [PoiInterior](../../world/instances/poi_interior.gd)，後者綁定地堡目錄、內容及照明；住宅需要明確分流，不能只換 `.tres` |
| 布局與地圖 | [InteriorLayout](../../world/instances/interior_layout.gd) 現有最多 60 模組／3 層，朝 -Y 延伸，地圖採 B1–B3。新 profile 須以大樓面與陳設群描述布局，定義 +Y 樓層高度、L1–L4 標籤、樓梯與可達性驗證；不沿用地堡房間池拼出小房間 |
| 保存 | [CheckpointSchema](../../core/checkpoint_schema.gd) 現在按地堡驗證布局與內容，需要與 profile 同步分流，新增樓層、陳設與住宅內容驗證；保存實際配置結果與狀態，不依 seed 重建 |
| 世界與版本 | 登錄不等於加入生成。新排程使用獨立 RNG，先做合法大場址與道路接近；不改既有四入口抽樣順序來偷接新棟。內容及格式若不相容，明確驗證版本或要求新局，不承諾舊檔遷移 |
| RV 與返回 | RV 留在持續運行的室外世界；無自動凍結或保護。入口停靠與返回點須驗證淨空，帶入設備不會自動連上 RV 服務。獨立 World3D 的外牆窗使用對應方向的簡化景觀與遮擋，避免誤導為可即時觀察室外 RV 的跨世界視窗 |
| 載入成本 | 現有室內一次組裝並烘焙導航，沒有任意逐層串流。四層先以共用模組、封閉上層及可見性分區控制成本；上方量體不建立完整可走房間或動態物件 |

新增組裝器先保留地堡既有行為，抽出兩者確實共用的最小接口即可。陳設、內容與燈光使用各自 RNG，並由穩定樓層 ID 派生；物資只由管理者首訪生成。驗證包含上下樓梯連通、目標可達、家具群不形成封閉分房、搬運淨空，以及未開放樓層封口。完整大樓面增加可見物件與長視線成本，需量測陳設密度及敵人感知，不能套用狹窄房間的效能估計。

## 7. 驗收方式與本次交付

本次只更新設計與概念圖：已人工檢查新版的對稱完整外觀、連續大樓面、柱列與美術方向，核對文件中的隨機內容及分階段範圍，並檢查相對連結及差異。室內圖只示意一個可能的陳設配置，不指定樓層用途；未啟動 Godot、未跑遊戲測試、未證實任何規劃中的通行、隨機生成或效能。

後續改到轉場／保存時，執行 `scripts/test.ps1 -TestFilter test_poi_transition_persistence.gd` 並按新增風險擴充既有測試。新 profile／定義須做 `validate()`／`validate_scene()`、多 seed 可達性與保存檢查、實際導航及搬運走查，核心轉場測試不能代替。人工驗收包含白天／夜間接近、L1–L4 樓梯連通、不同隨機配置、雙手搬運、重返與回到 RV。效能採相同機器／設定與既有地堡對照，記錄載入時間、幀時間及動態物件成本後訂預算，不預先宣稱整棟效能達標。

下一個適合開始的交付是階段 1：**簡單對稱的外殼、每層一個大空間與完整樓梯，能實際停車、上樓，再把一具大型引擎搬回 RV。**
