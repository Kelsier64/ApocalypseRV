# 玩家角色 Blender 建模委託書

> 可直接交給建模 AI。請把[參考圖片](references/player-masked-survivor.png)與本文件一起提供。圖片只用於輪廓和服裝款式參考；面具、換色結構、尺寸、骨架、分件與交付以文字規格為準。

## 1. 目標與交付範圍

為 Godot 4.7.2 第一人稱末日生存遊戲 **ApocalypseRV** 製作一名可近看、可動畫、可布娃娃倒地、可分離肢體的玩家角色。交付可編輯的 Blender 原檔及可匯入 Godot 的 glTF 2.0 Binary（`.glb`）。這是**完整全身角色**，不能只做第一人稱手臂、靜態雕像，或只有外觀而沒有蒙皮的模型。

優先完成外觀、拓樸、骨架、蒙皮與可分件結構。Godot 的布娃娃碰撞、關節限制、斷肢判定、相機與復活程式會在引擎內另做；請勿把 Blender 剛體模擬當作可直接在遊戲運作的布娃娃交付。

## 2. 外觀：以附圖為準

- 成年人、中等結實體型；頭部、肩膀和靴子形成清楚輪廓，整體是樸素、危險環境中的維修／搜救工作者。比例應是正常人類，**不要沿用 Raker 的長臂、駝背或怪物骨架比例**。
- 連身工作服的**預設展示色**為附圖的深灰綠；布面有輕微磨損和污漬，胸前口袋、前襟、腰帶與自然衣褶清楚，避免大量細碎裝飾。上臂及小腿各有橘色反光條，位置和寬度參照圖片。玩家日後可選工作服顏色，因此深綠色不可烘死在唯一的服裝貼圖中。
- 米色貼頭兜帽／頭套外面先做**一款純白、平滑、無圖案、無凹凸、無孔洞的面具**。附圖的黑色眼孔不納入這款預設面具。面具日後可由玩家自訂／替換，但本輪不需製作多款面具。
- 黑色手套與厚底黑色工作靴，手指及鞋底在近景仍能分辨。
- 色彩保持低飽和，符合遊戲的冷灰、深綠與土褐工業恐怖風格。附圖的燈光、房間、姿勢和畫面浮水印不是模型的一部分。不要增添武器、背包、品牌標誌或文字。
- 從正、側、背三面都要成立；背面衣服、靴子和頭套必須完整，不能只製作圖片可見的一面。

## 3. 尺寸、座標與效能目標

| 項目 | 要求 |
|---|---|
| Blender 單位 | Metric；Unit Scale 1.0；1 Blender 單位 = 1 公尺 |
| 建模身高 | **1.75 m**，中立站姿腳底到頭頂；先做灰模確認比例，再精修 |
| 原點 | 雙腳之間的地面，不放在骨盆；模型腳底 Z=0 |
| 朝向 | Blender 正面 `-Y`、上方 `+Z`；匯出 GLB 後正面 `+Z`、上方 `+Y`，由 Godot 外觀包裝節點轉 Y 180°，與現有怪物接入方式一致 |
| 變換 | 網格和 Armature 的物件 Scale=1、Rotation=0；不得用負縮放鏡像或在 Godot 執行時縮放物理骨架 |
| 網格預算 | 全身、衣物、面具、配件及封口合計目標 **8,000–12,000 個匯出後三角面**；若超出須列明原因 |
| 材質／貼圖 | 以 3–5 個材質為目標，至少分開可換色衣料、固定色反光條、純白面具；服裝與身體以 1024² 貼圖圖集為首版目標，切口可共用 512²；附 Base Color，建議 Roughness，Normal 視需要提供 |

**引擎接入提醒：** 現有玩家場景的碰撞膠囊高 1.50 m、半徑 0.40 m，腳底相對角色根節點在 Y=0.25 m；相機相對根節點高約 1.4146 m。這些是舊控制器尺寸，不是本模型應縮成 1.50 m 的指示。模型維持真實 1.75 m、Scale=1；正式接入前，開發端會以 RV 車門、走道、座椅、鏡頭和攀爬路線校對並調整控制器。不要把 0.25 m 腳底位移烘進 Blender 網格。

## 4. 網格、UV 與蒙皮

- 使用單一 Armature；衣服、身體、面具與配件可分成多個 Mesh，但應共用同一骨架與可讀的名稱。衣服下不會露出的皮膚可省略；頸部、袖口和切口附近需有必要的厚度，不能露出空心殼。
- 中立綁定姿勢採左右對稱 A-pose：雙臂離開軀幹約 35–45°，肘膝微彎，五指分開。肩、腋、肘、腕、髖、膝、踝各保留足夠環線供彎曲；衣服不應在舉手、坐下或爬行時大面積穿模。
- UV0 必須完整且可編輯；只允許有意識的鏡像共用，不得意外重疊。材質使用可匯出的 Principled BSDF；程序污漬要烘成貼圖，不把固定燈光陰影畫死在 Base Color。
- 工作服衣料使用可在 Godot 改色的**獨立材質或染色遮罩**：保留布料明暗、磨損與粗糙度，但 Base Color 不得含不可移除的深綠底色。交付時設定深灰綠為預設 tint，並展示至少另一種測試色，確認軀幹、袖子與褲管同步換色；橘色反光條、黑色手套／靴子、米色頭套與白面具不受衣料 tint 影響。換色 UI 與色票由遊戲端日後製作。
- 預設面具為獨立的 `mask_default` Mesh／材質，Base Color 純白 `#FFFFFF`，不繪製眼孔、花紋、污漬或固定表情。它隨 `head` 骨移動，與頭套及頭部主網格保持分離；保留穩定原點、朝向、大小與可替換位置，供日後用其他面具資產替換。面具自訂介面、面具變體與存檔規則不屬於本輪建模交付。
- 每頂點最多四根變形骨、權重總和正規化，沒有未加權頂點。面具、頭套跟隨頭骨；無線電與腰帶跟隨骨盆或明確的配件骨，不需替它們各做布娃娃剛體。
- 可以保留 Blender IK／控制骨供編輯，但 GLB 只輸出遊戲需要的階層與已烘焙動畫；控制骨不能意外成為大批物理骨。

## 5. 骨架：動畫完整，物理精簡

單一 `root` 位於腳底原點，`pelvis` 為子骨；主要鏈至少包含 `pelvis → spine_01 → spine_02 → chest → neck → head`、左右肩與上臂／前臂／手、左右大腿／小腿／腳及腳趾。左右名稱使用 `.L`／`.R`（以角色自身左右為準），所有交付檔維持同一組骨名、rest pose 和骨軸。每手五指可獨立彎曲，支援近景持物與攀爬。完整變形骨約 **55–70 根**，以實際需要為準。

請讓主要骨骼適合在 Godot 配置約 **15 個物理骨**：骨盆、胸、頭各一；左右上臂、前臂、手各一；左右大腿、小腿、腳各一。手指、衣角、面具及無線電不需要逐一模擬。肩髖、肘膝的骨軸需清楚且左右一致，方便之後設定關節限制。這 15 個是引擎布娃娃規劃，**不是要求在 Blender 內烘製 15 個剛體**。

## 6. 活體斷肢所需的分件

遊戲計畫允許玩家存活時失去肢體，並在死亡時使用全身布娃娃。請交付以下可獨立隱藏／輸出的主分件；衣袖、褲管和手套必須跟隨對應部位一起分離：

| 分件名稱 | 切口 |
|---|---|
| `body_torso` | 軀幹保留，不做腰斬 |
| `body_head` | 頸部；包含頭套和面具 |
| `body_upper_arm.L`、`.R` | 左右肩部 |
| `body_forearm.L`、`.R` | 左右肘部；各包含手套與手 |
| `body_thigh.L`、`.R` | 左右髖部 |
| `body_shin.L`、`.R` | 左右膝部；各包含靴子與腳 |

共 **10 個主分件、9 個預製切口**。每個切口都要有身體端及斷肢端封口，共 18 個封口面；完整角色時封口不可露出，分離後兩端都不能是空洞。封口可用簡化組織色塊、骨截面及衣料厚度；完整狀態接縫必須對齊，彎曲時不產生明顯裂縫。斷肢資產的權重不可繼續依賴已分離身體的骨架；同一手臂或腿的上段斷開時，下段需能跟著一同分離。請提供每個分件、切口兩端和所屬骨骼的對照表。

## 7. 動畫與姿勢檢查

首輪必要的獨立具名 Action：`idle`、`walk`、`jump`、`fall_loop`、`land`、`climb_loop`、`hang_idle`、`sit_driver`、`hold_small`、`carry_large`。請另提供 `injured_idle` 及單側缺臂、缺腿的中立測試姿勢，讓分件與蒙皮可以驗收；完整的受傷爬行動畫可在下一輪製作。布娃娃死亡不要求預先烘出所有倒地方向，短 `death_start` 可選配。

每段動作單獨命名、在原地播放：`root` 保持地面原點，不能烘進世界位移、旋轉或縮放；移動由 Godot 控制器負責。循環片段首尾無可見跳動。請記錄每段長度、fps、循環與否，以及雙腳接地時間。Blender IK、約束及 NLA 在匯出前須正確烘焙，Godot 匯入後不能變成一條混合長動畫。

蒙皮至少用下列姿勢逐一截圖檢查：雙手過頭、單手抓握、手指握拳、深彎肘膝、坐進駕駛座、向前攀爬、俯臥、側倒，以及左右上臂／前臂／大腿／小腿各自分離。沒有必要為測試姿勢製作正式動畫。

## 8. 交付檔案與驗收

1. `player_masked_survivor.blend`：保留可編輯網格、Armature、Action、分件、封口與清楚命名的 Collection。
2. `player_masked_survivor.glb`：完整中立角色、蒙皮、材質與已完成的獨立動畫；可在乾淨 Blender 場景及 Godot 4.7.2 重新匯入。
3. 貼圖 PNG 原檔與換色用材質／遮罩、獨立白面具，以及可獨立匯出的斷肢 Collection／資產；提供分件、切口封口、骨骼的對照表。
4. 正面、側面、背面、近距離頭部與手部、A-pose、坐姿、攀爬姿勢、布娃娃用主要骨架和至少一側手臂分離的預覽圖。
5. 一份 `README.md`：Blender 版本、輸出設定、身高、朝向、三角面、材質與骨骼數、Action 清單、貼圖尺寸、超出預算之處及尚未完成項目。

驗收以**實際 `.glb` 重匯入結果**為準：尺寸與朝向正確、骨名穩定、材質貼圖存在、工作服可整套換色而固定色部位不變、純白面具能單獨隱藏／替換、沒有缺權重或負縮放、動畫互相獨立、極端姿勢不爆點、完整接縫不顯眼、分離後兩端封口完整。圖片級渲染不能代替這些檢查。Godot 的物理骨、碰撞、換色與面具 UI、斷肢遊戲規則、第一人稱鏡頭與復活流程不屬於 Blender 交付完成的證明。
