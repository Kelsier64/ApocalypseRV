# Blender 角色與怪物製作規格 v2

日期：2026-09-22。依 GDD、角色場景及模型試接整理；v2 納入使用者明確要求的「玩家布娃娃、活著也會被怪物攻擊肢解，且影響行動與操作」。**這些為已確認的製作需求、尚未實作；具體切斷位置、面數、物理預算與能力規則仍是本文件建議，不是已量測的效能上限。** 本次只更新文件，沒有修改角色、物理或動畫程式，也沒有重新執行遊戲驗收。

## 1. 先製作什麼

玩家資產改為 **完整全身、可分離部位的蒙皮角色**，必須支援布娃娃及怪物攻擊肢解；不能只交付第一人稱手臂。第一人稱手部可從同一份全身來源衍生。怪物普通 Zombie 的預算與動作清單沿用，其他敵種按各自設計另立規格。

GDD 的玩家是第一人稱；現有玩家場景沒有全身或手臂蒙皮模型、布娃娃或分部位傷害。這些都需程式接入。**使用者已選定活體斷肢：斷肢可以在生命尚未歸零時發生，玩家仍可存活，但行動與操作須反映缺失部位。** 沒有已實作的槍械、玩家近戰、蹲下或衝刺，不把相應動作列為本輪必交；受傷爬行則納入此次新需求的製作提案。

## 2. 美術方向

- 工業恐怖、簡化幾何、低彩度；配合冷灰／土褐場景、深綠／奶油白 RV。
- 怪物建議使用偏灰膚色、暗眼窩、消瘦軀幹與略長前臂；手掌、頭頸與弓背形成主要輪廓。衣物可採破舊工作服或一般旅人衣著。這些造型是提案，GDD 沒有鎖定怪物外觀。
- 靠輪廓、大塊明暗與少量不對稱辨識角色；不要把辨識度放在毛孔、細血管或密集小破洞。
- 頭、手、肩肘與膝蓋優先分配面數。軀幹保留稜面感，關節以平滑法線和合理拓樸維持變形，不要求全模型 Flat Shade。
- 在實際約 540p 的 3D 畫面、霧中與車燈下檢查。GDD 不要求刻意像素方塊、VHS 或抖色。

## 3. 尺寸與座標

| 項目 | 本輪規格／現況 |
|---|---|
| Blender 單位 | Metric，Unit Scale 1.0；1 單位 = 1 公尺 |
| 新製 Zombie 高度 | 中立站姿腳底至頭頂 **1.50 m**，作為沿用現有膠囊的第一版目標；駝背用姿態表現 |
| 新製 Zombie 寬度 | 中立站姿肩寬建議 0.40–0.50 m、放鬆手臂的總寬盡量 ≤ 0.70 m；A-pose 展臂不受此寬度限制 |
| 模型原點 | 雙腳中間的地面，Blender Z=0；不要把角色物件原點放在骨盆 |
| Blender 朝向 | +Z 向上、-Y 為正面；匯出後資產 +Y 向上、+Z 為正面 |
| 本專案角色移動方向 | -Z；由 Godot 外觀包裝節點旋轉 Y 180°，沿用既有試接方式 |
| 物件變換 | 綁骨前整理 Mesh／Armature：Rotation=0、Scale=1；不保留負縮放。已綁骨或有動畫的舊資產勿直接套用變換，先在副本驗證 |
| 綁定姿勢 | 對稱 A-pose，手臂離軀幹約 35–45°、肘膝微彎；左右骨名以角色自身左右判定 |

**現有碰撞不能直接當成正常成人身高：** 玩家與 Zombie 膠囊皆為高度 1.5 m、半徑 0.4 m，中心相對角色根節點 Y=1，因此底部 Y=0.25、頂部 Y=1.75。玩家相機 Y≈1.4146，也是相對角色根節點。新模型仍以自己的腳底為零；Zombie 由既有 Godot `BodyMesh` 補 Y=0.25，不要把這 0.25 m 烘進模型。玩家尚無此模型包裝節點，需另行接入。

**現有模型有另一套來源尺寸：** `monster_export_test.glb` 原高 2.18 m，Godot `Model` 縮放約 0.6880734 才得到 1.5 m。若延續這份 Blender 來源，保留其 2.18 m 與既有比例即可；若重新製作 1.5 m 模型，接入時必須把 `Model` 縮放改為 1，不能再乘 0.688。兩條流程不可混用。

玩家完整模型建議以 **1.75 m 成人**為首版建模尺寸，與 Zombie 的 1.50 m 目標分開。這是新製作目標，不是現有玩家設定；接入前須一起校對膠囊、眼高、門洞、車內高度、座椅、方向盤與攀爬。布娃娃物理場景採最終尺寸及 Scale=1，避免靠執行時縮放整個物理骨架適配車廂。先做比例灰模進車驗證，再固定尺寸製作蒙皮與物理約束。

座標、三角化和變換的通用依據：[Godot 官方模型匯出建議](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/importing_3d_scenes/model_export_considerations.html)。

## 4. 網格與材質預算

所有面數以下列 **匯出後三角面（triangles）** 計算，含身體、衣服與配件；不是 Blender 四邊面數。

| 資產 | 建議三角面 | 材質槽 | 貼圖 | 變形骨 |
|---|---:|---:|---|---:|
| 普通 Zombie | 3,000–6,000；首版以 ≤6,000 為目標 | 1–2 | 一套 1024²；先用 512² 試畫也可 | 35–55 |
| 玩家完整全身，含衣服、所有斷面 | 8,000–12,000 | 目標 3–5 種材質，分開可換色衣料與可替換面具 | 身體／服裝一套 1024²；斷面可共用 512² | 55–70 |
| 玩家第一人稱手部，從全身衍生、選配獨立版本 | 合計 3,000–6,000 | 1–2，共用來源材質 | 共用或一套 1024² | 同全身手臂骨名與 rest pose |

- 現有試接怪物為 3,146 三角面、45 骨、2 材質，已可作起點，無須為追求面數上限而加細節。
- 普通怪物以 1 個蒙皮網格為主；衣服可在 Blender 分件編輯，交付時盡量合併或共用骨架／材質。只在確定需要替換時保留獨立配件。
- 玩家是分件例外：第 7 節的部位需能獨立隱藏／替換，共用同一骨架；材質分開可換色衣料、固定色反光條與可替換面具。材質數不等於繪製次數，分件會增加繪製成本。上表不包含同時生成多份屍體或第一人稱副本的總成本。玩家日後可選衣服顏色與自訂面具；首版面具規格見[玩家建模委託書](player-model-ai-brief.md)。
- 關節至少保留能支援彎曲的相鄰環線；肩腋要能舉手過頭，肘、膝、指節彎曲後不塌陷。不要把大量邊線花在看不到的衣服內層。
- 使用 UV0，避免意外重疊；對稱部位可刻意共用，傷疤／徽記等不對稱區另留空間。1024² 貼圖以約 8 px 島間距起步，並做邊緣延展，檢查縮小後接縫。
- Base Color 必交；Roughness 建議；Normal 選配。布／皮膚通常非金屬，金屬配件才使用相應 Metallic。不要把車燈高光或固定方向陰影畫死在底色。
- Blender 程序材質若要保留效果，先烘成可匯出的貼圖；交付簡單 Principled BSDF 材質。破衣優先用輪廓幾何與貼圖，透明混合只在確實必要時使用。
- LOD 本輪可延後；有群體需求時再做約 50%／25% 三角面的版本並量測。面數不能保證怪物群幀率，還有 AI、骨架、陰影及材質成本。

## 5. 骨架與蒙皮

使用單一 Armature、單一 `root`；`root` 在腳底原點，`pelvis` 是其子骨。軀幹可用 `pelvis → spine_01 → spine_02 → chest → neck → head`，左右肩、手臂、腿與腳接到相應部位。

- 左右成對骨用 `.L`／`.R`，例如 `upper_arm.L`、`forearm.L`、`hand.L`、`thigh.L`、`shin.L`、`foot.L`。這是新資產命名提案，現有來源骨名不必無故重命名。
- 怪物每手最低配置：拇指 2 節、食指 2 節、其餘三指以一組 2 節控制；近景玩家手建議五指各自控制。抓車動作要有可辨認的掌心接觸與握合。
- 每頂點最多 4 根骨影響、權重正規化、無漏權重頂點；以肩、腋、腕和髖的極端姿勢檢查。
- Blender 可以有 IK／控制骨，交付動畫需烘到輸出骨架。排除不必要控制器，但必須保留 `root` 和必要父骨；不能把 Export Deformation Bones Only 當成無條件勾選規則。
- 本輪不必做完整臉部表情、布料模擬或肌肉系統。玩家必須另製作分部位命中區與布娃娃碰撞；怪物是否也有布娃娃不由此次玩家需求推定。頭與下顎的簡單骨可選配。
- 攀爬前測試：雙手過頭、單手抓握另一手敲門、雙手向下砸擊、單膝高抬、深蹲式落地。這些姿勢比單純 T-pose 更能找出蒙皮問題。

## 6. 怪物動畫交付清單

**建議統一 30 fps 製作／烘焙，每個動作一個具名 Action。所有正式移動片段採原地動畫（in-place）：`root` 固定在原點、不旋轉、不縮放，骨盆可有步態起伏。世界位移由 Godot 的 CharacterBody3D、導航及攀爬程式負責。** 攀頂也不烘世界位移；身體相對抓點的演出需在接入時與程式對齊。

以下是待製作及待接入清單，目前程式不會因為 GLB 多了同名 Action 就自動切換。

| Action 名稱 | 循環 | 建議長度 | 用途與限制 |
|---|---|---|---|
| `idle` | 是 | 2–3 s | 站立、呼吸、輕微不安 |
| `walk` | 是 | 1.0–1.4 s | 遊蕩，現行速度約 1.0 m/s |
| `chase` | 是 | 0.6–0.9 s | 追擊，現行 2.5 m/s；可用急促步行，不必做高速奔跑 |
| `attack_front` | 否 | 0.7–1.0 s | 攻擊前方玩家，記錄接觸影格；現行冷卻 1.5 s |
| `climb_loop` | 是 | 0.8–1.2 s | 交替抓握、抬膝向上爬；腳底不能表現成地面行走 |
| `mantle` | 否 | 0.7–1.0 s | 越過頂緣並收腿，接入需配合既有登頂位移 |
| `hang_idle` | 是 | 1–2 s | 雙手掛住門面，持續抓車 |
| `attack_door` | 否 | 0.7–1.0 s | 一手支撐、一手敲擊／撕扯，身體仍掛住車 |
| `roof_settle` | 否 | 約 0.65 s | 登頂後低姿態站穩，配合現行穩定時間 |
| `attack_down` | 否 | 0.8–1.2 s | 彎腰向腳下屋頂砸擊，不能以向前揮拳代替 |
| `slip_loop` | 是 | 0.5–0.8 s | 抓握不足、身體下滑的姿態 |
| `fall_loop` | 是 | 0.5–0.8 s | 失去支撐自由落下；不自行沿時間軸降低 root |
| `land` | 否 | 0.3–0.5 s | 接觸地面後吸收衝擊，不能用固定時間預判落地 |
| `hit_react` | 否 | 0.2–0.4 s | 選配；目前受傷為閃白，動畫不代表新增硬直規則 |
| `death` | 否 | 0.8–1.2 s | 後續；目前死亡約 0.3 s 縮小消失，需要另改死亡流程 |

第一輪只先做 `idle`、`walk`、`chase`、`attack_front`、`climb_loop`、`attack_down`，證明完整匯入流程；掛門、攀頂、滑落與落地則在正式外觀驗收前補齊。

循環動作在 Blender 以首尾相同姿態驗證接縫；記錄每步接地影格、循環時間與設計速度，供程式調整播放速率，避免滑步。攻擊記錄接觸影格／秒數，但**目前傷害由程式即時判定，沒有已完成的動畫命中事件對接**；接動畫時另決定同步方式，不能讓動畫和程式各扣一次傷害。

## 7. 玩家全身、布娃娃與肢解

### 7.1 分件與切斷位置

首版建議採 **預製切口、隱藏原部位並生成對應斷肢**。先支援固定部位，任意位置即時切割另列後續研究；不是 Blender 匯出 GLB 就自帶切割功能。

| 網格名稱 | 數量 | 範圍 | 分離位置 |
|---|---:|---|---|
| `body_torso` | 1 | 胸腹與骨盆 | 本輪軀幹不攔腰分離 |
| `body_head` | 1 | 頭與上段頸 | 頸部 |
| `body_upper_arm.L/R` | 2 | 左右上臂 | 肩部 |
| `body_forearm.L/R` | 2 | 左右前臂，包含手 | 肘附近 |
| `body_thigh.L/R` | 2 | 左右大腿 | 髖附近 |
| `body_shin.L/R` | 2 | 左右小腿，包含腳 | 膝附近 |

合計 **10 個身體主分件、9 個切斷位置**。手腕、腳踝、手指與腰斬本輪不預設為必要切口，但手腕與腳踝仍要有動畫關節。服裝按同一切口分件；長袖、長褲不能在分離後仍連著兩側。衣物覆蓋且不會露出的內層皮膚可以省略，但切口附近需保留可見厚度。

每個切口交付留在身體端及斷肢端 **兩個封口面**，9 處共 18 個封口面，可採獨立網格／可切換區段。封口包含簡化組織色塊、骨截面及衣料厚度，不能露出空心洞；完整狀態隱藏封口，斷裂時只顯示相關兩面。接縫藏在衣縫或輪廓轉折，完整狀態的接縫頂點位置、法線與權重要匹配，彎曲時不裂開。

完整模型的肩、髖等接縫可跨父子骨平滑蒙皮。**獨立斷肢版本必須清除對已分離身體骨的權重並重新正規化**，或使用經驗證的獨立骨架轉換；不能把仍依賴胸／骨盆的蒙皮網格直接掛到普通剛體上，否則會拉長或變形。

### 7.2 動畫骨與物理骨分開規劃

玩家維持一套 55–70 根左右的完整變形骨架；五指各自可彎曲。物理模擬建議只用 **15 個主要物理骨**：骨盆、胸、頭各 1，左右上臂／前臂／手共 6，左右大腿／小腿／腳共 6。手指、臉、控制骨不各自加剛體。

Godot 以 `Skeleton3D` 下的 `PhysicalBoneSimulator3D` 管理 `PhysicalBone3D`。可由編輯器產生起始配置，再刪除多餘物理骨、調整碰撞及關節限制；生成結果不是完成品。參考 [Godot 官方布娃娃指南](https://docs.godotengine.org/en/stable/tutorials/physics/ragdoll_system.html)。

碰撞使用膠囊、盒或簡單凸形，避免高面數動態凹網格。肩髖限制擺動與扭轉，肘膝限制主要彎曲軸；約束軸需配合實際骨向調整。左右骨的 roll 要一致可解讀，不鏡像出負縮放。指尖、衣角等外觀不要求精準物理碰撞。相鄰肢體避免自碰撞打架；行走膠囊不能和自身布娃娃互相頂推。

**Blender 負責分件、封口、蒙皮與動作；Godot 負責關節限制、碰撞、質量、受擊衝量和模擬切換。** Blender 的剛體設定不作為本專案 GLB 交付的執行期契約。布娃娃是物理結果，不必在 Blender 烘製所有倒地動畫。

### 7.3 切換與斷肢的接入契約（待實作）

- 平常由角色控制器移動、動畫驅動骨架；死亡切換時複製當前全身姿態，再交給物理。停止原移動／攀爬附著，解除座位、UI 和放置狀態，處理手持物與鏡頭；不能繼續把屍體當成跟車角色移動。
- 建議屍體及斷肢成為獨立世界實體，與可復活玩家分開。切換時繼承當前世界速度，車上須包含所在點的車身平移／轉動速度，避免重複加上兩次車速；死亡位置受座椅／牆擠壓也要測試。
- 分離前擷取該段當前姿態與速度，隱藏原本網格並停用對應命中區／物理碰撞，再生成含封口的斷肢。原本骨架可保留以維持動畫索引，不能只隱藏網格而留下看不見的物理手臂。
- 若整條手臂從肩斷開，斷肢需包含當下仍存在的上臂、前臂及手；可用獨立小骨架和物理關節保持肘部彎曲。腿部同理。不能回到 A-pose，亦不能先斷前臂後又生成一隻完整手臂。
- 接縫表需列出 `part_id`、父部位、所屬網格、骨集合、切口兩端封口與斷肢資產。每部位僅能分離一次；父部位再分離時遵守已斷子部位狀態。避免一次攻擊的多個接觸重複扣血／重複生成。
- 活體命中區與物理碰撞分開；需判定攻擊位置、部位、方向、傷害類型與肢解授權。只靠現在的 `take_damage(amount)` 無法知道打到哪隻手。屍體能否繼續被攻擊及何時清理也需另定規則。
- 活體斷肢已確認：部位完整性和全身生命分開管理，斷手／斷腿不必直接等於死亡。是否斷裂由有效命中、部位損傷與攻擊類型規則決定；不得讓每次普通接觸都必定肢解。閾值及怪物攻擊種類尚未定值。
- 斷腿觸發失衡倒地時，短暫物理與後續可操作爬行要分階段接管。先從當前物理姿態及地面淨空轉回受傷控制器，再播放爬行動畫；純全身布娃娃不會自動成為可操控角色。移動與碰撞只能有一個有效控制者。

現行玩家死亡 2 秒後只回滿血，不會重建身體。新系統要處理復活時恢復部位／蒙皮／命中區、屍體去留與鏡頭重綁；不能只沿用原 `_respawn()`。活著的缺肢狀態不得被既有回滿血或載入流程意外重置。保存格式也尚未包含玩家缺失部位或屍體：活體部位狀態需納入檢查點及舊檔相容，屍體保存／清理策略另定。死亡代價、失血速度、止血與斷肢治療本次不假定已完成。

### 7.4 活體斷肢能力規則（建議首版）

以下用於推導模型與動畫交付範圍；「活體斷肢影響操作」已確認，但這張表的具體玩法仍為提案。可用手指手及其連到軀幹的手臂鏈完整，可用腿同理。先斷前臂後再斷上臂不重複減少可用手數。

| 身體狀況 | 建議行動與操作 | 需要的呈現 |
|---|---|---|
| 一隻手臂／前臂缺失 | 可走路；小型單手道具改由健側手使用；禁止雙手搬運與攀爬 | 左／右各一套單手持物或可混合姿態，缺失側停止抓點 IK |
| 雙手皆不可用 | 雙腿完整時仍能走路；禁止拿取、使用需手操作的設備、維修、攀爬與駕駛 | 空手／缺臂站走，禁止殘存動畫繼續呈現操作 |
| 一條腿／小腿缺失 | 失衡倒地，首版轉低姿態爬行；禁止站走、跳躍和攀爬 | 左／右缺腿倒地銜接與爬行；不先追加單腳跳整套動作 |
| 雙腿皆不可用 | 至少一隻可用手時可拖行；無可用手時停留原地，仍可看向周圍 | 雙臂拖行；單臂拖行分左右；無法移動的待機 |
| 駕駛中失去必要部位 | 首版建議至少一隻可用手及雙腿完整才能駕駛；不符合時解除控制並啟用既有安全停車流程 | 停止方向盤／踏板 IK，按座位及障礙狀況銜接倒地或離座 |
| 頭部分離 | 建議直接死亡，不作可操控的無頭生存 | 頭部斷肢與剩餘軀幹布娃娃 |

能力需求應附在操作／道具上，不只藏在動畫內；同一限制要覆蓋鍵盤、互動介面、持續中的維修與駕駛流程。失去手持能力時，掉落當前物品或安全取消搬移，維持原物品 ID 與庫存所有權，不複製或吞掉道具。混合傷勢依可用手／腿交集判定，不讓某個動畫狀態恢復已失去的能力。止血、假肢、接回肢體與永久殘疾都未因此自動納入本輪功能。

### 7.5 玩家動畫與第一人稱呈現

完整全身最低包含站立、行走、跳躍／落地、攀爬、坐姿駕駛、小物持握與大型物品雙手搬運；上半身與手部姿態需能配合移動。這些動畫仍需新程式接入。布娃娃接管後停止動畫覆寫物理骨的姿態。

另預留活體受傷動作：`injured_idle`、`hold_onehand_L/R`、`crawl_missing_leg_L/R`、`crawl_no_legs`、`crawl_onearm_L/R`、`prone_idle`，以及由物理倒地接到俯臥／爬行的過渡。名稱是新資產提案；單手持物可採上半身覆蓋，無須複製所有完整走路片段。最後採用的能力表若調整，動畫清單同步收斂。受傷移動需要新控制器、低姿態碰撞與相機高度，僅隱藏腿部模型不足以達成。

若另外做第一人稱手部版本，必須共用部位狀態；左手被移除後，第一人稱左手也要消失，不能留下可操作的「第二雙手」。本機鏡頭內可隱藏頭部或近景遮擋網格，但世界模型／屍體仍須完整顯示存活部位。死亡鏡頭先建議穩定旁觀視角，不直接跟隨旋轉的頭部剛體；鏡頭方案未定案。

先驗收全身比例、無縫分件、倒地與一側手臂分離，再完成其餘切口與近景手部精修。這可提早找出碰撞、蒙皮和接縫問題。

## 8. 匯出與交付

交付 `.blend` 原始檔、`.glb`、貼圖原檔，以及一份資產 README。README 列出 Blender 版本、身高、朝向、三角面、材質／骨骼數、Action 清單、循環與接觸影格、使用的匯出設定和素材來源。

建議正式新資產使用 `assets/models/monster/zombie_01/zombie_01.glb`；這是提議路徑，尚未建立。Blender 工作檔可留在既有外部建模專案並另行備份，Godot 專案以 GLB 作交付資產。

1. 在副本或專用匯出 Collection 中，只包含必要網格與骨架，排除攝影機、燈光、參考物與地板。
2. 輸出 glTF 2.0 Binary（`.glb`），包含蒙皮、所需材質／貼圖及具名動畫。先只匯出 `idle` 和 `walk` 確認，再輸出完整清單。
3. 檢查三角化結果、法線和 UV。保留工作檔可編輯拓樸，確定匯出結果沒有意外高細分或重複網格。
4. 烘焙約束／IK 的輸出姿態；依實際 Blender 版本選擇 Action／NLA 匯出模式，確認每個動作獨立且沒有意外合成一條長動畫。不要假設選項名稱在各版本完全相同。
5. 新空白場景重匯入 GLB，檢查 1 m 參考尺、正面、腳底、材質及所有動畫；以實際輸出結果為準。
6. Godot 中透過外觀子場景包裝 GLB，生命、碰撞、導航和位移仍由原角色場景管理，不從 Blender 自動產生角色碰撞。

玩家另交付完整分件 GLB、兩端封口、各切口所需的斷肢資產／可匯出 Collection，以及部位對照表。所有版本使用相同單位、骨名、rest pose 與明確的來源座標轉換。Godot 的布娃娃、斷肢和命中區場景需另外建立，不宣稱 GLB 本身包含可玩的肢解系統。

**不要直接覆蓋目前試接檔：** `monster_model_visual.gd` 仍硬讀 `Model/AnimationPlayer` 與 `TEST_InPlace`；`test_monster_model.gd` 也固定檢查 45 骨、2 材質、2.18 m、`MONSTER_Rig/Skeleton3D/MONSTER_Mesh` 和測試片段。新資產需要配套修改外觀腳本、動畫切換和對應測試。保留原試接資產作對照，不把這些暫時名稱當成永久美術規格。

## 9. 驗收順序

- 灰模：身高／朝向／腳底正確，能放進真實 RV 走道與門洞；攀爬、砸頂姿態輪廓清楚。
- 蒙皮：上述極端姿勢無爆點、肩腋塌陷或明顯自穿；衣服不與身體大面積穿插。
- 動畫：每段獨立、循環不跳、不累積 root 位移；不同播放速度下步態仍可用。
- 引擎：正式追擊、受傷、攀牆、掛門、登頂、砸頂、墜落和車內追擊逐項檢查；標記哪些仍未接動畫。
- 玩家布娃娃：站立、移動、攀爬、坐駕駛座、車內及行駛中 RV 上倒地，確認切換姿態連續、沒有爆飛或重複車速、鏡頭與控制權正確。
- 玩家肢解：9 個切口逐一測試兩端封口、衣服分離、命中區停用和速度繼承；測試先斷子部位再斷父部位、同一擊多次接觸與重複攻擊。屍體全身物理和分離部位不得留下重複碰撞。
- 玩家生命週期：復活恢復完整身體與操作；第一人稱副本同步、屍體／斷肢清理、存讀檔行為與最終玩法一致。活體缺肢時逐一驗收持物、搬運、攀爬、維修、駕駛、跳躍、倒地轉爬行，以及混合缺肢狀態的限制。
- 視覺：近景、10 m／25 m、陰天、夜間車燈、霧與低解析度下可辨識；以實機為準，不以 Blender 高品質渲染代替。
- 交付：模型及動畫接入後執行適用測試與專案統一 runner；物理變動依 AGENTS 做遊戲視窗驗收。車內導航已有歷史失敗，和新美術造成的問題分開追蹤。
