# Lethal Company 視覺風格與 ApocalypseRV 差距研究

日期：2026-09-17。範圍：研究、畫面對照與後續方向；本次未修改遊戲畫面或玩法。

## 結論

Lethal Company 的辨識度不能簡化成「密錄器濾鏡」。從官方商店公開畫面觀察，更適合把它描述為：**透過頭盔面罩看見的低精度工業世界，搭配強烈明暗分區、粗糙邊緣與帶有圖像化特徵的材質。** 這是本研究的美術歸納，不是作者公開宣告的風格名稱。

ApocalypseRV 上一輪完成了低解析、老舊材質、冷灰霧與模型變體，但仍偏向「加了霧與髒污的低模原型」。缺少的主要是模型輪廓、明暗組織、結構材質與近景呈現；繼續增加樹數或全畫面噪點，改善會有限。

原有 [恐怖氛圍研究](lethal-company-horror-atmosphere.md) 著重玩法與資訊衰退，其「接近損壞的監視器或工作設備」是感受比喻，不能當成原作採用密錄器攝影或某個 shader 的證據。

## 一、參考來源與證據界線

1. [Lethal Company 官方 Steam 頁面](https://store.steampowered.com/app/1966720/Lethal_Company/)：本次實際查看官方圖庫中的手持路牌／黑暗工業走道、室外手電筒／大型設施、紅色櫃子／橘色工作服／終端艙內畫面，以及頁面預告播放片段。觀察對象是官方公開素材，未使用玩家加裝畫質模組的畫面。
2. [Zeekerss 官方預告](https://www.youtube.com/watch?v=m5RB0Ej1mFg)：確認作者發布來源；本次動態觀察限於 Steam 嵌入預告片段，沒有完成逐幀分析或原作實機測量。
3. [Unrecord 官方 Steam 頁面](https://store.steampowered.com/app/2381520/Unrecord/)：開發者明確將其定義為警員隨身攝影機視角，並以錄影影像的視覺錯覺為美術方向，可用來區分真正以 bodycam 為核心的作品。
4. [Godot 4.6：Screen-reading shaders](https://docs.godotengine.org/en/4.6/tutorials/shaders/screen-reading_shaders.html)：核對現行 Compatibility 的技術限制。

以下關於原作的描述限於可見特徵。沒有取得原作 shader 或完整渲染設定，因此不宣稱已證實其描邊演算法、內部解析度、色階數、霧演算法或後製參數。官方圖庫也不代表每張地圖、每個版本與每種天候均有相同效果。

## 二、是密錄器風格嗎？

**有「透過設備觀看」的共同感受，但不是同一套視覺目標。**

| 比較 | 密錄器方向常追求的觀感 | 本次觀察到的 Lethal Company 特徵 |
|---|---|---|
| 世界表現 | 讓影像看似實地拍攝 | 明顯簡化的幾何、粗糙材質與不精確的輪廓 |
| 視角框架 | 攝影機鏡頭、曝光與運動的存在感 | 上下黑色面罩邊緣、工具與手部佔據近景、設備式 HUD |
| 明暗 | 攝影感可以是主要目標 | 很暗的背景與少數強烈光源、清楚的物件色塊互相襯托 |
| 適合借用 | 有節制的暗角、有限的可視範圍 | 面罩感、材質暗邊、明暗分區、工業結構與局部光色 |

表中是美術方向比較，不是所有密錄器遊戲都必然具有的技術清單。魚眼、動態顆粒、強烈晃動和色差不應成為下一輪的預設做法。若角色沒有戴頭盔的設定，也不應為模仿原作硬加厚重頭盔遮罩；可先比較極弱暗角與無遮罩兩版。

## 三、目前畫面具體差在哪裡

對照依據為上一輪的 [驗收截圖](../validation/2026-09-17-industrial-art.md)，不是本次重新啟動遊戲的實測。

| 項目 | 目前問題 | 建議方向 |
|---|---|---|
| 明暗組織 | 室外大面積落在灰褐中間亮度；有樹影，但亮面、陰影、遠霧的層次仍單調 | 近景保留深暗遮擋，中景留下可行走的亮度，遠景由霧吃掉細節；以入口燈或車燈建立焦點 |
| 植被輪廓 | 松樹雖有變體，仍一眼可讀成堆疊多角錐；灌叢像縮小的樹冠 | 打破完整層狀外殼，增加歪斜主幹、斷枝、樹冠缺口與不等長分枝，降低規律玩具感 |
| 建築量體 | 維修廠在截圖中像小棚屋，煙囪與附屬件尚未形成設施規模 | 用較高的主要立面、架空管架、深門廊與局部高牆，讓設施成為路線終點的視覺主體 |
| 材質 | 同一掉漆／噪聲分布於許多表面，容易成為均勻斑點 | 先畫接縫、面板、邊緣暗線、大塊油漬，再加入小磨耗；材質需描述結構與使用痕跡 |
| 近景物品 | 形體與邊緣還偏方塊原型，光照辨識不足 | 手持工具、儀表、門框先做輪廓與材質分區；用少量暗邊與局部高光建立體積 |
| 霧與光 | 霧主要是均勻遠距灰化，暖燈影響範圍小 | 讓亮燈在暗背景前可辨認，近景保留對比；局部光暈先在樣板中評估 |
| 顏色 | 多數物件被壓向相近的灰綠褐色 | 保留有功能的強調色：鏽紅櫃、暗黃警示、綠色儀表；RV 維持深綠／奶油白識別 |
| 畫面處理 | 現有復古效果主要是取樣像素格、微量抖色與輕微對比 | 先改善未加效果的基礎畫面，再比較解析度、暗部曲線與少量邊緣效果 |

### 程式檢查所得

- `world/outdoor_presentation.gd` 已有約 540px 高的 3D 縮放，以及 UI 分離；單純再降低解析度不是主要缺口。
- `world/terrain/retro.gdshader` 的對比係數只有 1.055，並以 `/100.0` 加入固定抖色；沒有離散色階或幾何描邊。不能把目前微量抖色稱為已完成原作的整套粗糙渲染風格。
- `world/industrial_art.gd` 用共用掉漆圖與程序噪聲產生多類材質，缺少依物件設計的接縫、結構與大尺度髒污。
- `world/terrain/forest_meshes.gd` 的樹冠仍是分層六點環與尖頂，解釋了畫面中反覆出現的多角錐輪廓。
- 上輪未改造副本室內 3D 美術，且室內停用室外復古效果；若把整個探索流程當作目標，室內外風格的一致性必須另納入工作。

## 四、下一輪應先製作一個可比較的美術樣板

建議先固定「RV 停車處 → 短段林路 → 維修廠入口」作為樣板，保留相同攝影位置及顯示尺寸；風格成立後才擴展至程序世界。不要再次以全世界加樹、加噪聲當成主要驗收。

### 優先 1：模型輪廓與明暗

- 重做少量代表性樹與灌木，測試有缺口的輪廓；保留清楚通行路徑。
- 強化一個入口的高低量體、門框凹陷、管線與遮棚；需增加真實可辨認結構，而非只有表面裝飾。
- 固定三層亮度：暗前景、中景通行帶、霧中遠景。門口與車內的燈光須有清楚照亮面及未照亮面。
- 對照亮度正常的灰階截圖；若去掉顏色後仍是一整片灰，先改光影與構圖。

### 優先 2：有結構的原創材質

- 做金屬面板、混凝土、樹皮、針葉／枯枝四類材質，各有不同尺度與磨耗分布。
- 可用 image_gen 產生原始素材，但需要求大塊污漬、結構暗線、簡化色塊與節制細節；不要再只要求寫實的無縫髒污。
- 面板接縫與邊緣可透過原創貼圖、幾何或局部材質完成，先處理近景設備與入口門。
- 材質本身的老舊仍須與耐久損傷分離，保留修復回饋。

### 優先 3：有限度的畫面與鏡頭呈現

- 在同一場景比較現況、強化明暗版、再加少量暗邊／暗角版；一次只改一組因素。
- 低解析保持可選，互動文字與 UI 保持清楚；原生解析度也需成立。
- 暗邊優先用於近景工具與硬表面，不把每片樹葉都描成黑線，避免視覺噪音與效能浪費。
- 頭盔邊緣只作為角色設定成立時的候選；不要以縮窄 FOV 或強烈晃動代替場景壓迫感。

### Compatibility 的限制

Godot 4.6 官方文件指出，螢幕法線／粗糙度紋理僅支援 Forward+，不支援 Compatibility。因此不可直接採用網路上依賴 `hint_normal_roughness_texture` 的描邊 shader，宣稱能放進目前專案。

可先評估材質內的暗線、少數物件的幾何外殼描邊，或另行測試相容的深度邊緣方案。這些是待驗證候選，尚未實作，也不能據此推定必須切換渲染器。官方畫面中看見的光暈／霧中亮區同樣不能證明原作採用哪一種體積光演算法。

## 五、驗收方式與建議決策

1. 固定公路、林路、入口、RV 艙內四個視角，維持同 seed、位置與輸出尺寸。
2. 同時看原生與復古版；原生版也應能讀出荒廢設施與粗糙工業風格。
3. 畫面需有主要暗區、可通行中間亮度、少數亮焦點；保留近距離物品與威脅辨識。
4. 樹冠不能一眼看成重複多角錐；建築從遠處必須有量體識別，近處有入口層次。
5. 開關後製後，主體風格仍成立；不能靠滿屏髒污掩蓋形體問題。
6. 樣板完成後，再量測影格時間、植被透明材質成本、陰影與新增繪製批次；本次未做新效能測試。

**建議決策：先重做一個入口樣板的模型、材質與光影，確認「長得像」再擴展；密錄器／面罩效果排在後面。** 本文件是研究建議，並不表示下一輪實作已獲確認或完成。
