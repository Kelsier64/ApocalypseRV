# 《Lethal Company》恐怖氛圍設計研究

日期：2026-09-16

## 結論

《Lethal Company》的恐怖核心不是怪物外觀或跳臉事件，而是把玩家放進一個具有工作目標的循環，然後隨探索深度逐步奪走資訊、通訊、機動力與退路。玩家為了收益自行決定延長冒險，因此遭遇危險時會產生「這是我自己貪心造成的」後悔感。

可將其核心概括為：

> 可理解的目標 + 不斷惡化的條件 + 不完整但可推理的資訊 + 玩家主動承擔的風險。

怪物的作用，是把這些壓力兌現，而不是單獨承擔全部恐怖效果。

## 一、以貪心驅動玩家進入危險

玩家必須回收廢料、達成公司配額，並用收益購買手電筒、對講機及其他工具。遊戲不需要用劇情強迫玩家走進黑暗；只要讓下一件物資具有足夠價值，玩家就會主動多搜一個房間、多待一分鐘。

這個設計形成三層壓力：

1. 沒有足夠物資，可能無法達成配額。
2. 搜得越多，越不願意空手撤退。
3. 隊伍累積得越成功，就越害怕一次團滅造成的損失。

因此，恐怖並非單純來自「會不會死」，而是來自「現在撤退是否太早」以及「再拿一件是否值得」。

## 二、用資訊衰退取代持續驚嚇

玩家深入設施後，會同時失去多種資訊與能力：

- **視覺資訊**：黑暗、狹窄光束、濃霧和遮擋限制可見距離。
- **空間資訊**：相似房間、岔路與程序化配置削弱方向感。
- **隊伍資訊**：距離語音會隨空間與距離衰減，隊友也可能突然失去回應。
- **操作能力**：物品佔據手部與攜帶欄位，重物會降低機動性；雙手物品會限制工具使用。
- **時間餘裕**：玩家拖得越晚，撤退和戶外活動通常越危險。

這些限制不必立即造成傷害。它們先讓玩家無法確認威脅，再讓玩家自行想像最壞的可能。隊友剛才還在隔壁說話，下一秒只剩寂靜，往往比直接播放怪物音效更有效。

## 三、把語音通訊變成遊戲機制

距離語音不是附加的社交功能，而是《Lethal Company》的主要恐怖系統之一：

- 聲音的方向、距離與遮擋能表示隊友位置。
- 隔牆的腳步或尖叫只提供部分事件資訊。
- 隊友死亡會自然切斷對話，寂靜本身成為訊號。
- 對講機可以恢復遠距通訊，但需要物品欄、電量及操作成本。
- 船上的監控員能看到雷達訊號，卻不一定知道隊友正在逃跑、搬運重物，還是已經死亡。

這使「保持聯絡」具有價格。玩家必須在攜帶更多物資、攜帶生存工具和維持通訊之間取捨。若隊伍全程使用不受遊戲空間限制的外部語音，這部分恐怖感便會顯著減弱。

## 四、讓怪物成為行為規則，而非純數值敵人

有效的怪物不只具有不同血量和移動速度，而是要求玩家採取互相衝突的行為：

- **Coil-Head**：被注視時停止移動，迫使玩家持續付出視野與注意力。
- **Bracken**：需要偶爾確認位置，但長時間盯視可能使情況惡化。
- **Eyeless Dog**：主要依靠聲音尋找目標，使說話、移動與工具噪音變成危險。
- **Ghost Girl**：只有被纏上的玩家能直接看見，讓隊伍成員無法共享相同的現實。

單一規則通常可以理解和學習；恐怖來自數種規則同時出現。例如玩家必須盯住 Coil-Head，卻也需要轉頭確認 Bracken，或者必須保持安靜，卻又需要透過語音警告隊友。

這是一種「公平的不確定性」：

- 怪物規則可以學會。
- 當下資訊永遠不完整。
- 多套規則的組合難以完全預測。

玩家死亡後通常能理解自己犯了什麼錯，因而願意再次嘗試；但下一局的空間、隊友和威脅組合仍然不同。

## 五、建立安全感，再逐步破壞它

飛船提供照明、終端、監控和撤離能力，看似是一個安全基地。但戶外生物可以靠近，噪音能引來危險，返程隊員也可能把威脅帶回來。

這種設計比「所有地方始終同樣危險」更有效：

1. 玩家先建立安全區的心理模型。
2. 遊戲提供細微的異常聲音或跡象。
3. 威脅開始接近或侵入安全區。
4. 原本用來逃生的空間變成新的危險來源。

恐怖的來源不是沒有安全感，而是原本可靠的安全感正在失效。

## 六、利用喜劇恢復玩家的感受力

低模角色、笨拙搬運、喇叭、布娃娃死亡和隊友失誤會自然產生喜劇。這不是對恐怖的削弱，而是壓力節奏的一部分。

喜劇與恐怖都使用相似結構：

> 建立期待 → 延遲結果 → 突然釋放能量。

結果可能是怪物突襲，也可能是隊友以荒謬方式死亡。笑聲讓玩家暫時放鬆，使下一個異常重新具有衝擊力；如果遊戲全程維持最高壓力，玩家反而容易麻木。

此外，系統互動產生的意外通常比固定腳本更耐玩。物理效果、玩家語音、怪物規則和環境危險互相碰撞，能自然產生看似精心安排的恐怖或喜劇時機。

## 七、Low-fi 視覺是一種資訊控制

低解析、有限色彩、濃霧、工業空間與簡單模型除了降低製作成本，也能服務恐怖設計：

- 隱藏怪物細節和實際距離。
- 讓靜止物體、陰影和敵人輪廓互相混淆。
- 降低玩家從精細動畫預判攻擊的能力。
- 使畫面接近損壞的監視器或工作設備，而非清晰的英雄視角。
- 把感知重心轉移到聲音、移動和玩家想像。

關鍵不是單純降低畫質，而是控制哪些資訊清楚、哪些資訊保持曖昧。重要互動與撤退方向仍然需要可讀，威脅的種類與距離則可以保持不確定。

## 八、對 ApocalypseRV 的應用

ApocalypseRV 現有的「搜刮 → 回收 → 製作汽油 → 再出發」循環，已具備轉化為恐怖壓力循環的基礎。設計上應優先強化玩家的決策壓力與資訊限制，而不只是增加殭屍數量。

### 8.1 建立玩家可控制的撤退風險

可使用以下條件逐步惡化世界：

- 天色變暗，視野和道路辨識能力下降。
- 天候或濃霧逐漸增強。
- 停留時間越長，建築周圍聚集的怪物越多。
- RV 的油、電和設備狀態持續消耗。
- 某些道路或安全停靠點只在特定時間前可用。

不宜使用毫無預兆的倒數即死。玩家需要看見風險正在增加，並在「現在回去」與「再搜一間」之間作出有意義的選擇。

### 8.2 將 RV 聲音設計成主要情報介面

目前的攀車、破門、拆頂和設備損壞系統很適合以聲音傳遞：

- 車外刮擦提示怪物正在抓附哪一側。
- 車頂腳步表示威脅已登頂，但不立即顯示精確位置。
- 門板變形、玻璃震動和鎖扣聲表示結構耐久正在惡化。
- 設備受到攻擊時，聲音應依材質與位置不同。
- 引擎故障、供電不穩和低油量使用不同但可學會的聲音模式。

引擎、雨勢、發電機和製作設備可以遮蔽怪物聲音，形成實際取捨：啟動設備能提供功能，卻降低環境感知。

### 8.3 設計感知方式互異的怪物

可避免所有敵人都使用相同的「看見玩家後追擊」模型，例如：

- 追蹤引擎聲，但較難發現熄火、熄燈 RV 的怪物。
- 被車燈直接照射時停止攀爬，但會促使玩家持續耗電的怪物。
- 只在玩家操作平板或製作設備時接近的怪物。
- 會模仿設備警報、敲門聲或物品掉落聲的怪物。
- 玩家注視時躲藏，專門繞到 RV 另一側破壞的怪物。
- 對快速移動敏感，但能被緩慢搬運和蹲行避開的怪物。

每種敵人應先有清楚、可學習的單一規則，再利用敵人組合製造衝突；不宜主要依靠隱藏加成、血量膨脹或無提示瞬殺。

### 8.4 讓 RV 從避難所逐步變成陷阱

RV 應該先是可靠的移動基地，再被分階段侵蝕：

1. 車外出現聲響或影子。
2. 怪物開始攀附、遮擋視野或攻擊外部設備。
3. 車門、牆板或屋頂受到可感知的損壞。
4. 照明、引擎或生產能力局部失效。
5. 怪物打開破口並進入車內。
6. 玩家必須選擇駕駛逃離、維修、反制或棄車。

各階段需要足夠的聲音與視覺預兆，使玩家能理解危險並作出反應。若怪物一出現便直接進入車內，安全感尚未建立，侵入便不會產生應有的衝擊。

### 8.5 修正會消除後果的系統

目前「玩家死亡約兩秒後原地恢復滿血」容易使死亡變成低成本重置；室內外敵人不能跨入口，也可能讓入口成為絕對安全線。

若要保留快速回到遊戲的節奏，可以讓死亡留下可恢復但有意義的後果，例如：

- 掉落背包，需要重新取回。
- 世界時間前進或天候惡化。
- RV 消耗部分油電，或有一項設備受損。
- 暫時傷勢降低搬運、奔跑或感知能力。
- 怪物保留位置，使玩家不能用死亡重置危險。

入口也不一定要允許所有敵人跨越，但應避免玩家百分之百確定門後永遠安全。可以用門外伏擊、返程事件、聲音延續或特定敵人跨區追蹤來保留不確定性。

## 九、建議的實作優先順序

### P0：先建立恐怖循環

1. 加入可讀的時間或環境惡化。
2. 讓停留越久具有更高風險，但同時保留更多收益機會。
3. 給死亡和失敗加入持續性成本。
4. 確保玩家永遠有撤退選項，而不是只能等待被殺。

### P1：建立聲音資訊層

1. 完成 RV 外殼、車頂、車門和設備的方向性音效。
2. 加入引擎與天候造成的聲音遮蔽。
3. 讓怪物在正式現身前留下可以學習的聲音跡象。
4. 避免使用過多非空間化背景音效，以免破壞方向判斷。

### P2：增加規則型怪物

1. 先製作兩種感知方式完全不同的敵人。
2. 分別測試其單獨遭遇是否公平、可理解。
3. 再測試兩種敵人同時出現時，是否產生有趣的行為衝突。
4. 使用生成權重和冷卻控制組合，不以單純增加數量提高難度。

### P3：多人版本再導入社交資訊差

若未來加入合作模式，可進一步使用：

- 依距離和遮擋衰減的語音。
- 需要電量和手部操作的無線電。
- 司機、搜刮者和留守者看到不同資訊的角色分工。
- 死亡後限制對存活玩家通訊。
- RV 監控畫面只顯示不完整訊號，而不直接標記敵人名稱與狀態。

單人階段不應硬套距離語音；更適合先以 RV 聲音、遠端感測器、有限監控和設備狀態取代多人資訊差。

## 十、設計檢核表

每次新增恐怖內容時，可檢查以下問題：

- 玩家是否為了可理解的利益主動承擔風險？
- 危險發生前是否存在可感知但不完整的跡象？
- 玩家是否能從失敗中推理出原因？
- 解法是否有成本，而不是永遠正確的固定答案？
- 這個敵人是否改變玩家行為，而不只是要求更多傷害？
- 安全區失效前是否已成功建立安全感？
- 高壓事件之間是否有足夠的平靜或喜劇空間？
- 聲音是否提供方向、距離和材質資訊？
- 畫面模糊是否服務資訊控制，而不是單純降低可用性？
- 多種系統組合後是否能產生非腳本化事件？
