# RV 底盤共用儲存與設備入口

日期：2026-09-16。依使用者確認的修訂實作；電池插槽拆下時，電池成為掉落道具。此文件取代上一份互動修正中油箱／材料架／獨立點火的現況說明。

## 已完成行為

| 元件 | 現行規則 |
|---|---|
| 底盤 | 保存燃油、材料數量、完整道具記錄。預設容量分別為 100、300 單位、24 格 |
| 電池插槽 | Equipment，可搬移／維修；同車只接通一顆電池。設備定義集中名稱、重量與 HP |
| 電池道具 | 保存 ID、電量與容量；倉庫／背包中的電池不供電 |
| 道具箱 | E 開啟不耗電共用倉庫，存入／取出道具；電量和耐久顯示在按鈕上 |
| 加油孔 | 手持汽油罐 E 加入底盤，返還空罐；本身不保存燃油，也不增加容量 |
| 引擎 | 駕駛座 B 與平板按鈕共用同一狀態；獨立引擎開關已移除 |

- 開始搬移、支撐脫落或插槽損壞時，電池生成於車體外的 WorldEntities，繼承車輛點速度；插槽清空。取消搬移不會再生或自動收回電池。
- 短 E 裝入／交換電池；長 E 取出至背包。交換可使用原背包格；直接取出仍需空間。
- 拆除道具箱或加油孔，不會帶走資源或減少容量。失效設備停止互動，修好或安裝新的入口恢復使用。
- 材料是數字，由分解機取得，製作與維修扣除。面板顯示數量，移除領出材料包的操作。滿庫分解等待，退款和遷移超額保留。
- 倉庫保存完整道具記錄，先檢查目的地容量、大型道具限制，再完成轉移。過期 UI 按鈕不會誤取另一件物品。
- 道具箱無電可開；平板仍需電，無電時可進駕駛座手動發動，耗油配合發電機恢復充電。

## 保存與相容

Checkpoint 與 VehicleSnapshot 升為版本 2。電池存在插槽 service，底盤保存道具陣列、燃油及各容量。讀取後重建插槽不會額外掉出舊電池。

版本 1 在記憶體中轉換，通過驗證才載入；讀取不覆寫原存檔：

- 已安裝油箱的油量加總到原車底盤；舊電池轉成新插槽狀態。
- 舊材料架變成道具箱，舊油箱變成加油孔。
- 背包、世界、已訪 POI 與分解機輸入中的材料包，轉入第一台保存車輛的材料數量，移除原項目。
- 游離油箱燃油轉入第一台保存車輛，必要時提高燃油容量以保留存量。
- 材料超額保留，可消耗，直到有空間才繼續新增。
- 舊資源路徑保留相容轉接；正式場景使用 item_box／fuel_port。未知版本或無法驗證的資料拒絕載入。

### 存檔重載收尾修正

追加並行測試曾出現一次 Godot 原生崩潰，獨立執行也出現腳本資源殘留。弱參照驗證證明電池實例本身都有釋放。測試使用相同 seed 1790440711 重現，並等待背景導航烘焙完成，避免快速銷毀尚在建立的世界。

BatteryState 改用接受 Dictionary 的建構式還原，移除自我引用靜態工廠後，同 seed 的 verbose 執行成功，無崩潰、腳本資源殘留或退出錯誤。型別保持精確的 BatterySocket。此腳本資源現象與 [Godot 的相關回報](https://github.com/godotengine/godot/issues/122022) 相符，但未以原生除錯器證明那次崩潰的唯一原因。驗證 API 參考 [NavigationServer3D](https://docs.godotengine.org/en/4.5/classes/class_navigationserver3d.html)。

舊的同步單元測試（攀爬、背包、戰鬥、導航、POI 資源）統一改為 call_deferred 啟動，避免在 SceneTree 初始化階段就載入／釋放腳本並退出引擎。攀爬與背包測試曾出現斷言 PASS 後的原生退出異常；改動保留所有原斷言。導航邊緣支撐測試原先使用沒有碰撞 RID 的 Node3D，且初始化時會直接走未入樹 fallback；現在使用 CharacterBody3D 並等待物理同步，實際驗證原本的邊緣重疊斷言。

## 範圍限制

- 攀爬回放是腳本移車；正式輪驅使用自動物理回歸，本次沒有重跑 5 km 長途／翻車／群體怪物專項。
- 道具容量按件數計格；燃油、材料與倉庫道具尚未納入動態載重。
- 設備仍使用獨立凍結剛體，未把大型外掛的碰撞力矩合併到底盤。
- 容量與經濟參數是原型預設。無多槽存檔、室內直接存檔、多人或多顆電池並聯功能。
